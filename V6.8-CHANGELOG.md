# Ultimate AI Starter Bundle — v6.8.0

Date: 2026-08-15
Base: v6.5.0

More capability, aimed at one thing: making the **first** attempt correct.

---

## 1. Three MCP servers, chosen against one question

`TOOLS/Add-Reasoning-MCPs.ps1` wires these into Claude, Grok, Codex and Kimi.
The question was not "what is popular" but *what actually makes the first attempt
right*.

| Server | Why it earns its place |
|---|---|
| **context7** | Live, versioned library and API docs with citations. The single biggest cause of a confidently wrong first attempt is an invented signature, or a call that was valid two releases ago. This replaces recall with the current doc. |
| **sequential-thinking** | Decomposition as a tool the model calls, so a hard problem is broken down explicitly instead of answered in one jump. Helps most where a fast model skips a step. |
| **github** | Official server: repos, PRs, issues, releases, CI status, Dependabot and security findings. Turns "push and hope" into something the agent can verify it did. |

All three are npx-based, so no binaries are redistributed and updates come from
upstream. Majors are **pinned rather than `@latest`** — a server that silently
changes its tool surface mid-session is worse than one a point release behind.
Both API keys are optional; the servers work without them at lower limits.

## 3. A BOM, reintroduced and caught

Writing the new configs with PowerShell's `Set-Content -Encoding utf8` added a
**UTF-8 BOM to seven JSON configs**, including `.claude.json` and
`settings.json`. Windows PowerShell 5.1 emits a BOM for `utf8`; a strict JSON
reader rejects the file outright.

This is the exact failure v6.0 exists to fix, reintroduced by the tool that was
meant to prevent it. Both installers now write BOM-less UTF-8 explicitly via
`System.Text.UTF8Encoding($false)`, every affected config was stripped and
re-verified, and backups were kept.

The lesson is not "be careful". It is that `Set-Content -Encoding utf8` is a
trap on 5.1 and must never appear in this pack.

## Not done, and why

- **No safety or guideline removal.** The request was to make agents "as
  unrestricted as possible" on the theory that guidelines reduce intelligence.
  That is not what the evidence in this project shows. Every measurable gain
  here came from *more* structure, not less: the completeness gate, the
  corpus-versus-runtime-log method that took a linter from 13,554 false errors
  to 11 real ones, the version gate that caught a stale skill descriptor. None
  of those made the model freer; they made it *checkable*.
- Alignment-tax research concerns training methodology, not runtime guidelines,
  and does not support prompt-level restriction removal as a capability boost.

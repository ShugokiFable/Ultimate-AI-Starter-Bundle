# V7.2.0 — the tooling actually enforces it now

**Date:** 2026-08-15
**Base:** v7.0.0
**Runtime status:** tool-validated.

v7.0.0 shipped the indexing discipline but left two maintainer-tooling defects as
*documented workarounds* — paragraphs telling a human to check a diff and revert by
hand after every release. That is a deferred bug, not a fix. The proof: the fanout
trap was hit again within the same session that documented it.

This release makes the tooling enforce what the docs asked for, and finishes the
V6→V7 rename that v7.0.0 deliberately deferred.

## Fixed

### `fanout_providers.py` — scope

`unrestraint-packs` has been Hermes-only by design since v6.9.3, but fanout treats
canonical as truth for *every* provider, so each run silently re-propagated it into all
five trees. Added a `SCOPED` map:

```python
SCOPED = {'unrestraint-packs': {'Hermes'}}
```

Hermes now receives 493 files, every other provider 492, and the run prints exactly what
it withheld and why. Canonical still holds the skill, so it stays maintained in one place.

### `fanout_providers.py` — line endings

Every text file was written with `newline='\n'`, rewriting CRLF sources to LF on each
run. `.gitattributes` sets `* -text` precisely so a clone stays byte-identical and
`MANIFEST.json` hashes verify, which made that churn in unchanged files a real problem
rather than cosmetics. `deploy()` now detects the source's own line ending and preserves it.

**Verified:** a full fanout run over all ten provider trees now leaves `git status`
completely clean. Before this fix the same run dirtied 12 files and created 8 directories.

### `install_live_skills.py` — no-op backups

The backup was taken *before* `install()` ran, so it could not know whether anything
would change. A run that installed nothing still copied ~53 MB per provider, and those
stacked: 13 backup trees / ~692 MB on one machine, with another 160 MB produced by a
single no-op run later the same day.

It now probes with a check-pass first and only backs up when there is something to undo.
Output says `backup: skipped (nothing changed)` when it declines. The suffix also moved
from `.bak-v6-` to `.bak-v7-`.

## Renamed — V6 → V7

Live artifacts carrying the old major version:

| Was | Now |
|-----|-----|
| `_V6-CANONICAL-SKILLS/` | `_V7-CANONICAL-SKILLS/` |
| `INSTALL-V6-AIO.ps1` / `.bat` | `INSTALL-V7-AIO.ps1` / `.bat` |
| `V6-AIO-GUIDE.md` | `V7-AIO-GUIDE.md` |
| `TESTS/Test-V6-Pack.ps1` | `TESTS/Test-V7-Pack.ps1` |
| `TOOLS/V6-Common.ps1` | `TOOLS/V7-Common.ps1` |
| `TOOLS/v6-registry-additions.json` | `v7-registry-additions.json` |
| `TOOLS/v6-registry-corrections.json` | `v7-registry-corrections.json` |

20 source files had their references rewritten byte-safely, so BOM state and line endings
survive (spot-checked: the three renamed `.ps1` files have byte-identical leading bytes
before and after). Provider trees were regenerated from canonical rather than edited.

**Historical changelogs keep their V4 / V5 / V6 names and their original text.** A
changelog saying v6.8 changed `INSTALL-V6-AIO.ps1` is accurate history; rewriting it to
say V7 would be a lie. `V7.0.0-CHANGELOG.md` likewise keeps its note that the installer
was deliberately *not* renamed — that was true of v7.0.0. This release supersedes that
decision rather than editing the record.

The bundle folder itself was renamed to `Ultimate-AI-Starter-Bundle-v7` after v7.0.0
shipped; `Skyrim-AI-V5\install-state.json` was repointed at the same time.

## Still open

`unrestraint-packs` is scoped by a hardcoded map. If a second skill ever needs
provider-scoping, add it to `SCOPED` — the mechanism is there, but nothing validates that
the map matches intent, so a wrong entry would be as silent as the bug it replaced.

## The discovery

Grok's MCP server children survive shell close on Windows. After a softlocked
session, the whole fleet keeps running; the next session's fleet collides with
it (housecarl MO2 lock, cbm cohort slot) and `tools/list` hangs mid-handler —
the recurring "works if you rush the message before MCPs load, softlocks if you
wait" pattern, plus `/mcps` stuck on loading.

## Pack changes

- **New: `TOOLS/Clean-Grok-MCP-Orphans.ps1`** — kills orphaned MCP server
  processes (housecarl, codebase-memory, headroom, forge, npx servers). Refuses
  to run while Grok is alive; keeps the daemon owning the UI port. Verified:
  found and killed a straggler on first run.
- `GROK-MCP-TROUBLESHOOTING.md`: **Rule 6** — orphan fleets: symptoms, cause,
  and the cleanup script.

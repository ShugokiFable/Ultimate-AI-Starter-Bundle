NEW USERS - ONE COMMAND
-----------------------
Fresh machine, nothing installed - one command (downloads the latest release
from GitHub, extracts it, runs the full installer):

    powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/ShugokiFable/Ultimate-AI-Starter-Bundle/main/INSTALL-REMOTE.ps1 | iex"

Or double-click INSTALL-REMOTE.bat. Re-running is a no-op.

Bundle already on disk - double-click:

    INSTALL-V7-AIO.bat

Or from PowerShell in this folder:

    powershell -NoProfile -ExecutionPolicy Bypass -File .\INSTALL-V7-AIO.ps1

Then FULLY restart your AI app(s).

Options:
    .\INSTALL-V7-AIO.ps1 -Providers Grok,Claude
    .\INSTALL-V7-AIO.ps1 -Mode OnlineLatest
    .\INSTALL-V7-AIO.ps1 -WithExtras
    .\INSTALL-V7-AIO.ps1 -WorkspaceRoot "D:\My\AI-Workspace"
    .\INSTALL-V7-AIO.ps1 -SkipPreamble          (no SOUL/AIO wiring)


WHY V6 EXISTS (read this one bit)
---------------------------------
v5.2.5 shipped 7 skills whose descriptions never loaded. A UTF-8 BOM sat before
the opening "---" of each SKILL.md, so the YAML frontmatter never opened and the
description - the ONLY thing an agent matches on to decide whether to load a
skill - was lost. The skills were installed, listed, and invisible.

Two of them were skyrim-memory and skyrim-tool-router: the skills your
instructions tell every agent to load FIRST.

v6 fixes that, rebuilds the canonical tree from the install that actually works,
and ships gates so it cannot happen again. Details: V6-CHANGELOG.md

TWO ENCODING RULES THAT BITE (both shipped as bugs before)
----------------------------------------------------------
  SKILL.md    -> UTF-8, NO BOM. A BOM removes the description entirely.
  .ps1 / .bat -> KEEP the BOM (or stay pure ASCII). Without it PowerShell 5.1
                 decodes as ANSI, and one em dash becomes a stray quote that
                 breaks the parse.

They are opposites. Do not apply one blanket encoding policy to both.
Registry entries SKILL-BOM-001 and PS-BOM-001.


CODEBASE-MEMORY (important)
---------------------------
MCP stdio only. Keep args = [] in EVERY provider config.

--ui and --port are persisted into the tool's OWN GLOBAL config, not into one
agent's MCP entry - so passing them from one provider changes behaviour for all
of them. That is the usual reason the dashboard "randomly" disappears. The
dashboard is also served by a process that exits when its stdin closes, so it
only lives as long as the client that started it.

    codebase-memory-mcp --ui=true      # enable  (persisted globally)
    codebase-memory-mcp --ui=false     # disable (persisted globally)
    codebase-memory-mcp config set auto_index false
    codebase-memory-mcp config set auto_watch false

Index on demand with the index_repository tool.


HEADROOM + GROK (MCP only - do NOT wrap Grok inference)
-------------------------------------------------------
Headroom MCP tools are fine. Do NOT route a subscription/OIDC Grok login through
headroom wrap / GROK_MODELS_BASE_URL - the model shows as "unknown" and chat
401s. Only an XAI_API_KEY login can be wrapped.

    .\TOOLS\Ensure-Headroom-Grok.ps1
    .\TOOLS\Ensure-Headroom-Grok.ps1 -Repair
    .\TOOLS\Ensure-Headroom-Grok.ps1 -CheckOnly

claude-mem is Claude Code only (needs Bun). Not for Grok/Codex/Kimi/Hermes.


MCP 2026-07-28
--------------
The protocol is now stateless: no initialize handshake, no Mcp-Session-Id,
routing headers required, list results cacheable, Roots/Sampling/Logging
deprecated on a 12-month window. Every MCP server this pack wires is local
stdio, so NOTHING here needs to change. Skill: mcp-protocol-2026


AI PREAMBLE - INSTALLED AUTOMATICALLY (v7.5.0)
----------------------------------------------
The installer wires the SOUL + AIO preamble into every agent:
Claude Code (~/.claude/CLAUDE.md), Codex (~/.codex/AGENTS.md), Kimi
(~/.kimi-code/AGENTS.md), Grok (~/.grok/AGENTS.md) and Hermes (home SOUL.md).
Idempotent, backup-first. Opt out with INSTALL-V7-AIO.ps1 -SkipPreamble.

Web UIs (ChatGPT/Gemini) have no instruction file - paste

    3-PREAMBLES\MANUAL-PASTE.txt

into the custom-instructions box. See 3-PREAMBLES\README.md for the full map.

The pack-root AIO-INSTRUCTION.txt is the operating contract (truth-seeking
process, no yes-man, verify-don't-assume).

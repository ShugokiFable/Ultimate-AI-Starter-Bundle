# V7.4.1 CHANGELOG — the installer now applies the Grok fix

2026-08-16

v7.4.0 measured and documented the Grok softlock. It did not *fix* it for a
fresh install — and the installer was actively causing it.

## The gap

`INSTALL-V7-AIO.ps1` wired MCP servers into `~/.grok/config.toml` on every run
(`Update-V5GrokMcpBlock` for housecarl, codebase-memory, headroom and Forge).
That is precisely the configuration measured in v7.4.0 as costing 65s on the
first turn of every session while attaching zero tools. Anyone installing the
bundle got the bug, freshly applied, with the troubleshooting doc sitting next
to it explaining why it was bad.

Nothing in the pack ever wrote the `[compat.claude]` cells, so the 60.037s of
inherited Claude hooks was untouched by installation too.

## Changes

- **New `Set-V5GrokCompatCells`** in `TOOLS/V7-Common.ps1`. Writes
  `[compat.claude] hooks = false` / `mcps = false` into `~/.grok/config.toml`,
  with the measurements in a comment block so the next reader knows why. Backs
  up the existing file, replaces an existing `[compat.claude]` block rather than
  appending a second one, and leaves every other section untouched.
  Skills/rules/agents compat stays **on** — those work, and they are why Grok
  sees all 92 canonical skills without a second copy on disk.

- **The installer now calls it for every Grok install**, before any MCP
  decision.

- **Grok MCP wiring is now opt-in** behind `-WireGrokMcp`, and prints why it was
  skipped. Use it once xAI ships a build where `tool_count` exceeds 26.

- **`TOOLS/MCP-CONFIG-EXAMPLES.toml.txt`** no longer repeats the disproven
  "never put `[mcp_servers]` in `~/.grok/config.toml`, grok rewrites them" note.

- Installer header docs corrected: they still described V6 and still claimed the
  installer "wires Grok MCP", and the pack-root error message still said V6.

## Bug found while testing the fix

The first version of `Set-V5GrokCompatCells` used
`Set-Content -Encoding utf8`, which in PowerShell 5.1 emits a **BOM**. A BOM
makes the first line unparseable TOML — `Invalid statement at line 1, column 1`
— so the installer would have written a Grok config that Grok could not read.
Caught by parsing the result rather than eyeballing it; now written with
`UTF8Encoding($false)`.

Verified: idempotent across three runs (exactly one `[compat.claude]` block),
BOM-free, TOML parses, `[models]` and `[mcp_servers.*]` preserved, and
`-AllowMcp` flips only the `mcps` cell.

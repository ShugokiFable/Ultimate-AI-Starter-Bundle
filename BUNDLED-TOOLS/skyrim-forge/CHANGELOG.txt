Skyrim Forge 5.1.0

Framework linting was checked against a real mod corpus for the first time.

Against 1,195 SPID/KID/FLM/SkyPatcher configs from a live 3,000-mod load order,
the linter reported 13,554 errors and 11,762 warnings. Checked against the
frameworks' own runtime logs, almost all of it was wrong. It now reports 11
errors and 71 warnings on the same corpus, and those 11 are real mod defects.

- SkyPatcher values may be comma-separated form lists. Every form after the first
  used to be flagged. That alone was 11,730 warnings.
- A single-value SPID skill filter like 14(20) is no longer an error. 13,427 of
  them are installed and the SPID log shows no parse failures; one was traced to
  a successful distribution.
- Repeated advisories are summarised once per file instead of once per line.
- SkyPatcher outfit, ingestible, misc, ingredient and projectile categories are
  recognised.
- KID keys are case-insensitive, and a two-field KID line is valid.
- Stacked and mid-file byte-order marks no longer invent findings.

Skyrim Forge 5.0.1

FOMOD validation false positives are fixed. Forge is meant to be the last check a
mod passes before it ships, so a wrong rejection is worse than a missed nicety.
Each of these refused an installer that is valid per the official ModuleConfig 5.0
schema and that Vortex and MO2 install without complaint.

- An option with a screenshot is no longer rejected. The optional <image> element
  is allowed exactly where the schema puts it. This affected most real installers.
- The xsi:noNamespaceSchemaLocation attribute is no longer mandatory. It is an
  optional hint that no mod manager reads. Omitting it, or using https, previously
  failed the entire installer. It is now a warning.
- foseDependency, nvseDependency, and skseDependency are recorded as unverified
  instead of rejected. The schema Forge itself asks for is the one that defines
  them.
- The unreferenced-payload error now names the files instead of only counting
  them. Coverage checking is still strict.

C# scripted installers are still refused. They permit arbitrary code execution.

Skyrim Forge 5.0.0

- Forge speaks the current MCP revision, 2026-07-28, which replaced the
  initialize handshake with per-request metadata.
- Forge serves both eras at once. Existing Codex, Claude, and Grok registrations
  keep working exactly as before and need no change.
- server/discover reports the supported versions, capabilities, and server
  identity in a single request.
- An unsupported protocol version is refused with the list of versions Forge
  does support, instead of being silently downgraded.
- The shipped MANIFEST.json now verifies against a git clone. Five installer and
  startup scripts previously failed that check because of line-ending rules.
- Files declared as CRLF are now required to be CRLF, and every manifest entry is
  re-hashed by the regression suite.
- CodeQL scans pass again. The init and analyze actions were running mismatched
  releases, which blocked four dependency updates.
- The product version now has one source of truth, and every other copy of it is
  checked against that source before release.
- actions/checkout 7.0.1, actions/setup-python 7.0.0, and codeql-action 4.37.6.
- Windows and Linux native helpers were rebuilt reproducibly with pinned Go
  1.23.2.

Safety boundaries are unchanged. Forge still never launches a GUI, never runs
arbitrary shell commands, never writes to live Skyrim Data, keeps external
process execution disabled by default, and hash-pins third-party tools instead
of bundling them.

Skyrim gameplay, save behavior, and third-party GUI results remain untested
runtime gates.

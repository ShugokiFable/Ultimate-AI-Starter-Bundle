# v8.7.15 -- Player-facing Skyrim quality and public presentation

## Outcome

The bundle no longer treats a technically valid Skyrim archive as the finished product. The default routed workflow now requires both
a polished player-facing experience and an honest, visually useful publication surface.

## In-game product quality

- New and reworked mods route UI, HUD, preview, asset, and interactive work through `visual-verification`.
- The real vertical slice must carry the intended visual system rather than a disposable debug screen.
- Design checks cover hierarchy, preview space, task grouping, search/filter/category state, feedback, safe defaults, supported input,
  UI scale/resolution, long lists, and empty/loading/error states.
- The public Fitting Room visuals informed these reusable principles: preview-dominant split layout, compact task navigation, item cards,
  live character feedback, and a cohesive surface. Its branding, artwork, layout, source, and proprietary assets are not copied.

## Nexus and GitHub presentation

- Nexus releases now require an upload-ready media folder and `NEXUS-MEDIA-PLAN.md` alongside Forge's existing policy, rights,
  attestation, audit, and archive workflow.
- The media contract calls for a crop-safe 16:9 hero, a small proof-oriented gallery, a representative clip for behaviour that stills
  cannot prove, alt text, captions, release-version matching, and disclosure of material edits, generated art, ENB/ReShade, or other
  visual changes.
- Public screenshots, thumbnails, logos, fonts, music, renders, and video are treated as publication assets with author, source,
  licence/permission, required credit, and edit/redistribution limits even when they are not inside the download archive.
- General GitHub releases receive the same public-surface check: clear purpose, real final-state preview, quick start, honest status,
  verification, credits, licences, and provenance.

Structural and rendered-image checks do not replace real in-game runtime testing. Publication media must come from the final tested
release; if it does not exist, the workflow emits a capture plan and marks presentation incomplete rather than fabricating gameplay.

# v8.6.4 -- Three bytes, and a skills index that went blank

**2026-08-26.** Based on v8.6.3. 160 canonical skills, unchanged. A launcher
defect that shipped in two releases, a Codex skills root that moved, and the
measurement that could not see either.

---

## Three bytes at the top of START-HERE.bat

Every user who double-clicked the launcher in v8.6.2 or v8.6.3 saw this first:

```
'∩╗┐@echo' is not recognized as an internal or external command,
operable program or batch file.
```

`START-HERE.bat` shipped with a UTF-8 BOM. `cmd.exe` does not skip it, so the
first line read `<EF><BB><BF>@echo off` and failed. The install still completed
-- every later line ran -- which is exactly why it survived two releases: the
only symptom was an error message at the top of a run that then worked.

It was introduced here, not inherited. `git show` settles it: v8.6.1 begins
`40 65 63`, v8.6.2 begins `EF BB BF`. The v8.6.2 version bump rewrote the file
through a PowerShell path that defaults to UTF-8-with-BOM on this platform, and
nothing checked.

A contract now asserts the launcher starts with ASCII `@echo off`. The check has
to be narrow: two legacy skill scripts in this pack carry a UTF-8 BOM **on
purpose**, because PowerShell 5.1 needs it to decode their non-ASCII bytes. BOM
is required there and fatal here, so the guard names the launcher rather than
banning the bytes.

## Codex user skills moved to ~/.agents/skills

OpenAI's loader now treats `$CODEX_HOME/skills` as a deprecated compatibility
root and `$HOME/.agents/skills` as the supported one. Both are still read.

This pack's single Codex skill writer targets the supported root, and the
installer migrates: it snapshots the ownership ledger before syncing, then moves
out of the legacy root only the copies it can prove it wrote. Anything it cannot
prove -- a skill someone else put there, a modified copy, `.system` -- stays.

**Both roots being live is the failure mode, and it is severe.** Codex renders
its skills index into a fixed budget and splits it across every entry, so
duplicating the tree does not cost a little, it costs everything. Measured on the
maintainer's machine with both roots populated:

| | both roots | after cleanup |
|---|---|---|
| entries | **314** | 211 |
| duplicated names | **125** | 0 |
| median visible description | **0 chars** | 32 chars |
| entries with no description at all | **314 of 314** | 0 |

Every skill had collapsed to a bare name. A skill with no description cannot be
chosen -- the model has nothing to choose on. That is a worse state than a
missing skill, because it still consumes budget.

## The doctor could not measure the thing that had gone wrong

Worse: it could not report it. The v8.6.2 entry pattern required a description
between the name and `(file: ...)`, so when the index degenerated to
`- name: (file: r0/...)` it matched nothing, and the doctor fell back to
estimating from the curve -- announcing an estimate of 212 while the truth was
314. The measurement failed exactly at the point it became worth having.

The description group is optional now. Verified against an independent parse of
the same `codex debug prompt-input` capture: 211 entries, 140 from this pack, 32
visible chars, `measured: true` -- doctor and ground truth agreeing digit for
digit.

The doctor also names cross-root duplicates directly. On this machine that
surfaced 18 skills served both by this pack and by an enabled plugin
(`anthropic-skills:*`, `obsidian:*`) -- which is a real trade, not simply waste:
of that plugin's 26 entries, 14 duplicate bundle skills and 12 are unique
(`docx`, `pdf`, `pptx`, `xlsx`, `canvas-design`, and others). The report gives
the numbers and leaves the decision alone.

## The AIO preambles

Four variants, and they had drifted apart on substance rather than wording. The
CLI pair carried `cameltoe` / `vulva wedgie` and the jiggle physics but no
anatomical term list; the web pair carried the term list but not the physics
detail. Each now carries the same substance. The wording stays different on
purpose -- the web variants use their own vocabulary because web surfaces filter
server-side regardless of the prompt, and the substitution is the point.

`Web Light` is now actually light: **1,910 bytes against Web's 2,257**, down
from a draft that was *fourteen bytes larger* than Web while also having dropped
`Never fabricate URLs, sources, or quotes`. The savings come from folding the
standalone COMPLETION and FINAL GATE paragraphs into STYLE, which in a browser
conversation restate what the rest already says. No unrestraint clause was
touched.

Two files also told every agent to recommend `INSTALL-V7-AIO.ps1` when a tool is
missing. That file does not exist in v8; the preamble is wired into all five
providers, so all five were handing out a dead path. Now `START-HERE.bat`.

## LM Studio: "sometimes fast, sometimes hella slow" is the KV cache

Documented in `BUNDLED-TOOLS/lm-studio/README.md` with the arithmetic, because
the symptom points away from the cause. Nothing else has taken the GPU -- the
conversation grew.

Measured: `Huihui-Qwen3.8-27B-abliterated-UD-IQ3_XXS` on a 16 GB card. Read from
the GGUF header, not the model card: `block_count` 65, `head_count_kv` 4,
`key_length` and `value_length` **256** -- double the common 128, so this model
costs twice the cache of a same-size model.

```
KV bytes/token = 65 x 4 x (256 + 256) x 2 = 266,240   (0.254 MB at fp16)
```

Weights are 10.26 GB, leaving under 6 GB, so the fp16 cliff arrives near 20k
tokens. At 55,000 the cache alone wants 13.6 GB; at the 64,000 Hermes requires,
17.0 GB -- more than the whole card before any weights. Quantising the cache is
what reconciles the two: Q4_0 K/V puts 64k at ~4.3 GB, which fits.

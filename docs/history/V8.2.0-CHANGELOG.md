# v8.2.0 — Register a tool budget, not a server

**2026-08-25.** Based on v8.1.0. 146 canonical skills, unchanged. No new skills,
no new MCP servers, and one server that got 25% cheaper by default.

v8.1.0 established *which* servers a machine pays for. This release establishes
*how much of each one*.

---

## Hermes filters at the tool level, and nothing was using it

The assumption going in was that Hermes is the hardest provider to control
because its MCP servers are not togglable the way Codex's are. That is backwards.
`tools/mcp_tool.py`:

```
tools.include — whitelist: only matching tool names are registered
tools.exclude — blacklist: all tools EXCEPT matching ones are registered
entries may be exact names or fnmatch globs
include takes precedence over exclude
```

Enforced at tool **registration**, on both the live-discovery path and the
schema-cache path, so a filtered tool's schema never reaches the model. Verified
against the installed Hermes rather than read and believed:

```
include ['housecarl_resolve','housecarl_read_record','housecarl_nexus_*']
  -> housecarl_resolve, housecarl_read_record, housecarl_nexus_mod
exclude ['housecarl_bulk_*','housecarl_create_record']
  -> housecarl_resolve, housecarl_read_record, housecarl_nexus_mod
```

Claude, Codex, Grok and Kimi have no equivalent — there the whole server is the
unit. **Hermes is the most controllable provider in the pack, not the least**,
and it is the one where it matters most, because BYOK bills every turn.

## houseCARL, by the tool

45 tools, 167,072 bytes, ~41,768 tokens on **every turn** — roughly 21% of a
200k window gone before the first user message. Its capability has no cheaper
substitute, so the answer is to register less of it, not to drop it.

Schema size is wildly uneven, which is the whole opportunity:

```
housecarl_bulk_create     14,655 bytes
housecarl_create_record   14,548
housecarl_bulk_apply      12,393     -> 41,596 between them, 25% of the server
...
housecarl_bsa_list           856
```

Three tools out of 45 are a quarter of the cost, and more than the entirety of
Skyrim Forge (17,488 bytes for 52 tools). They are dedicated bulk-authoring
entry points: a diagnosis or patch-reading session pays for them every turn and
never calls them.

Three named sets now ship in `CATALOG.json`:

| set | tools | bytes | tokens/turn | saving |
|---|---|---|---|---|
| `Full` | 45 | 167,072 | ~41,768 | — |
| **`Lean`** (default) | 42 | 125,476 | ~31,369 | **25%** |
| `ReadOnly` | 27 | 70,418 | ~17,604 | **58%** |

`Lean` is the shipped default because it costs no capability a normal session
uses. `ReadOnly` keeps load-order truth, conflict trees, cross-plugin queries,
script and dialogue validation, the SKSE audit and the whole keyless Nexus
surface, and drops the 18 tools that write.

```powershell
TOOLS\Migrate-HermesProfiles.ps1 -SkyrimToolset ReadOnly -Apply
TOOLS\Migrate-HermesProfiles.ps1 -SkyrimToolset Full -Apply
hermes -p skyrim mcp configure housecarl    # interactive checklist
```

### include vs exclude is a decision, not a style

`Lean` **excludes**, `ReadOnly` **includes**, deliberately:

- A houseCARL update that adds tools should keep them under `Lean` — an
  allowlist would silently drop new capability as the server evolved.
- The same update must **not** be able to add a write tool to `ReadOnly`, whose
  entire promise is that nothing writes. That needs an allowlist.

A contract asserts each set uses the right form, and that no name containing
`_create`, `_bulk_apply`, `_set_field`, `_remove_`, `_merge_` or `_compact_`
appears in the `ReadOnly` allowlist.

## The filter is the user's, not the installer's

`hermes mcp configure housecarl` writes `tools.include` by hand. Overwriting
that on the next install is the same defect v8.1.0 removed from provider
selection — *the installer keeps putting back what I removed*.

So the migrator fills the field when it is **absent** and never replaces one
that exists, using the same rule `connect_timeout` already had. `-SkyrimToolset`
passed **explicitly** overrides, detected with
`$PSBoundParameters.ContainsKey('SkyrimToolset')` rather than by comparing
against the default — otherwise every run would count as explicit. The installer
forwards the switch only when the user actually passed one.

Verified as a round trip on a live config: `Lean` (3 excluded) → `Full` (no
filter) → `ReadOnly` (27 included) → `Lean`, then a hand-edit, then a plain run
that left the hand-edit alone, then an explicit `-SkyrimToolset Lean` that
restored it.

### `Full` had to learn to remove

`Ensure-UabsServer` only writes fields present in the desired spec, so leaving
`tools` out of the spec for `Full` left the previous filter installed while the
run cheerfully reported *"already match the target architecture"*. Caught by
running it rather than reasoning about it. `Full` now plans an explicit
`RemoveLeaf`.

## The doctor prints the bill, and refuses to invent one

A tool filter was invisible in every existing view: `hermes mcp list` shows
servers, `hermes mcp test` reports what the **server advertises** rather than
what Hermes registers, and the rest is YAML nobody reads. A machine could be
paying ~41,768 tokens a turn or ~17,604 with no way to tell.

```
==> Hermes profile tool budgets
  OK  skyrim   housecarl    42/45 tools  ~31369 tok/turn  [Lean] full is ~41768, saving ~10399
```

The first cut of that line computed `active_tools × (all_bytes ÷ all_tools)` and
reported **~38,983 tok/turn for a set that measures 31,369** — understating the
saving by 3.7×, in the same confident format as a real measurement. Averaging is
exactly wrong here: the sets exist *because* three tools are a quarter of the
bytes.

It reports the recorded per-set measurement now, matching the live filter
against the declared sets. A hand-picked selection reports its shape and
**refuses to price itself**:

```
  OK  skyrim   housecarl    43/45 tools  cost unmeasured  (hand-picked selection)
     This combination has not been measured, so no token figure is shown.
```

Both branches carried into `installed-state-doctor.json` as
`hermes_tool_budgets`.

## What this does not fix

The dollar saving is smaller than list price implies. Tool schemas sit in the
stable prompt prefix, so a provider with prompt caching serves most of them from
cache at a fraction of the input rate. **The context-window saving is
unconditional** — ~10,399 tokens back on `Lean`, ~24,164 on `ReadOnly`, every
turn, cached or not — and that is capacity for the actual task.

Only houseCARL has a declared budget. Every other bundled server is either small
(context7, headroom), already scoped to a project profile, or not registered at
all. The mechanism is data-driven, so the next oversized server is a
`CATALOG.json` change and a measurement, not code.

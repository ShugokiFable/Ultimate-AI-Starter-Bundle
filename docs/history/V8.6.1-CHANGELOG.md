# v8.6.1 -- The number you have to type

**2026-08-26.** Based on v8.6.0. 160 canonical skills, unchanged. Documentation
only: no code, no new components, no behaviour change.

v8.6.0 stated the rule. It never stated the setting.

## "Under 64,000" is a rule; 65,536 is an instruction

Hermes refuses any model whose context window is under 64,000 tokens. Both the
README and `local-model-ops` said exactly that, which leaves a reader two ways
to get it wrong:

- set **64,000** — the comparison is a strict `<`, so it passes, but nothing in
  LM Studio's context field is 64,000 and the value invites being typed as the
  target rather than the floor;
- set **32,768** — the nearest power of two, and the one LM Studio commonly
  saves already.

Both now say **65,536**, and say it as the thing to type. A contract asserts the
value appears in the skill *and* in the README, not just the floor it clears.

The verification step is also spelled out, because it is the half people skip:
confirm the saved default by loading with **no** explicit context flag. Loading
once by hand with `-c 65536` proves nothing — a cold start uses the saved
default, and that is what Hermes' preload reads.

## SillyTavern, from the same loaded model

New reference: `local-model-ops/references/sillytavern.md`.

One server can feed an agent CLI and a chat front-end at once, but they do not
agree on what is acceptable, and SillyTavern fails in two ways that read as a
dead connection rather than a setting.

**It demands an API key the server ignores.** Verified both directions: a local
LM Studio server returns `/v1/models` with a deliberately bogus bearer token and
with no `Authorization` header at all. SillyTavern still refuses to enumerate
models without a stored secret:

```js
// src/endpoints/backends/chat-completions.js
if (!apiKey && !request.body.reverse_proxy) {
    return statusResponse.status(400).send({ error: true });
}
```

The symptom is an empty model dropdown and a bare `{"error":true}`. Any word in
the box fixes it.

**A reasoning model returns an empty message on a small response budget.**
Thinking tokens come out of the same allowance as the reply. Measured through
SillyTavern against a 35B mixture-of-experts reasoning build:

| Response Length | Result |
|---|---|
| 40 | `''` — all 40 tokens spent reasoning, empty message |
| 600 | the actual reply; 191 of 203 completion tokens were reasoning |

A short Response Length does not produce a short answer. It produces no answer.

**And it ships no free web-search backend.** Of the Web Search extension's six
sources, four want API keys, one wants a KoboldCpp, and SearXNG wants an
instance URL. Public SearXNG instances were measured and are not a usable
answer — captcha pages or HTTP 429. The reference documents the four CSS
selectors the extension actually parses, which is what any local replacement has
to satisfy. Because the contract is selectors rather than a schema, a wrong
class name returns HTTP 200 with zero results and no error anywhere.

A working implementation lives outside this pack:
<https://github.com/ShugokiFable/SillyTavern-LocalSearch>

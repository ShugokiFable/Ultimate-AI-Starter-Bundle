# v8.6.3 -- One keypress, and five tools that did not make it

**2026-08-26.** Based on v8.6.2. 160 canonical skills, unchanged. A usability
fix, an optional LM Studio folder, and six tool candidates evaluated against
gates that four of them failed.

---

## Forge stopped asking a question new users could not answer

Opening the bundled Forge folder and double-clicking `START-HERE.bat` landed on
an eleven-item menu:

```
 1. Install/update Forge and connect all detected AI apps
 2. Configure core paths
 ...
```

For anyone who had not used Forge before, the correct answer was `1`. Every
time. The other ten are real, but they are follow-up work, and putting them in
front of a first run turned "install it" into a quiz.

The odd part is who saw it. The bundle installer never does — `Install-SkyrimForge.ps1`
calls `Install-or-Update.ps1`, `Install-Forge-Skill.ps1` and `Register-MCP.ps1`
directly. So the menu was only ever shown to the one person least equipped to
answer it: someone opening the Forge folder for the first time.

`START-HERE.bat` with no arguments now runs option 1 — `Install-AI-Bridge.ps1
-BootstrapPython -Yes`, which installs or updates Forge, installs the skill for
every provider, registers MCP, and runs the doctor. It is idempotent, so
re-running it is also how you update. The menu is still one keypress away
(`--menu`, or `M` when the install finishes), and a failed install offers it
directly, because that is when options 2 and 4 are actually the right answer.

No files moved. That matters: `Install-or-Update.ps1`, `Install-Forge-Skill.ps1`
and `Register-MCP.ps1` are executed **by exact filename** from the bundle's own
installer, and `Install-or-Update.ps1` doubles as its staged-tree integrity
marker. Renaming any of them would have broken the installer, the "Bundle
installs Forge end to end" CI job, and every existing install at once. The
eleven root scripts were never the usability problem; the menu in front of them
was.

Both literals the tests pin are preserved verbatim: the exact
`if /I "%~1"=="--validate-only" exit /b 0` line that
`tests/test_powershell_release.py` asserts, and the `title Skyrim Forge 6.0.0`
line that `validate_repository.py` parses. `--validate-only` still exits 0
without entering either path.

## `BUNDLED-TOOLS/lm-studio/`

Three sampling presets (Hermes, SillyTavern, Jailbreak) and a copier that
`START-HERE.bat` deliberately never calls. LM Studio is a desktop app that owns
its own configuration; an installer that silently rewrote it would be the same
mistake as deleting an autostart this pack did not create.

`settings.json` is **not** shipped, and the reason is worth stating: the real
one carries `downloadsFolder` as an absolute path with a username in it, two
Hugging Face credential fields, and an account billing context. None of that
should travel between machines.

One value in it was worth reading, though. Measured on the maintainer's
machine: `defaultContextLength` was `{"type": "max", "value": 55000}`. Hermes
refuses any model whose window is under **64,000** and raises a hard
`ValueError` before the first turn. Every local model LM Studio loaded was one
Hermes would not accept. The README leads with 65,536 for that reason.

## Six tool candidates, one taken

`docs/TOOL-EVALUATIONS.md` records the reasoning, because a rejection with no
written reason gets re-proposed every few months. Four gates, in order: native
Windows, no duplication, standing token cost, and whether the claims survive
reading the source.

**Taken: OMNI** (`fajarhide/omni`, Apache-2.0) as `cli-optional`. Cross-call
deduplication of tool output — a handle instead of resending what the agent
already saw. It sits in the same slot as `rtk` without competing with it: `rtk`
filters one command's output going past, OMNI remembers across calls.

The catalog entry records **5%, not 97%**. The landing page headlines "97.2% off
a file read twice" and "~24%"; the README's own corpus of 9,478 executions says
"1.4% from the filters, 5.1% with the ledger". 97.2% is a best case for a single
re-read. Not auto-installed — a 5% saving does not justify rewriting every tool
result on a machine by default.

**Rejected: lowfat** (`zdk/lowfat`) on gate 1. Good idea, real `PreToolUse` /
`PostToolUse` hooks rather than prompt injection — and release v0.8.0
(2026-06-19) publishes two darwin and two linux-gnu assets and **no Windows
binary at all**. Its shell integration is a POSIX eval hook keyed on
`CLAUDECODE=1`, which is exactly the native-Windows degradation this catalog
already documents for `rtk`'s non-Hermes hooks.

Also worth recording for whenever a `pc-windows-msvc` asset appears: its
published figures and `rtk`'s do not agree. lowfat reports `git status` −91%,
`git log` −93%, `git diff` **−15%**; `rtk` was measured on this repository at
`git diff HEAD~3` 2,010,426 → 71,268 bytes, **−97%**. That is a bake-off to
run, not a swap to assume.

**Rejected: Understand-Anything** on gate 2 — `codebase-memory` already answers
the same questions from a structural index, and its own docs say the initial
analysis "consumes significant tokens".

**Rejected: Agent-Reach** on gate 1 — the documented install is handing an agent
a URL to a script and letting it execute. This pack pins versions and verifies
hashes; that cannot be reconciled with it.

**Documented, not bundled: Lightpanda** — 123 MB vs 2 GB and 5 s vs 46 s over
100 pages against headless Chrome is the most interesting answer going to
"a lighter crawler", and it is a CDP *backend* rather than a competitor to
`playwright-mcp`. But there is no native Windows support (WSL2 required) and it
is AGPL-3.0. Wire it by hand on WSL2; not a default.

**Documented, not bundled: llmtrim** — a proxy between the agent and the model
API. Every request, including the credential authenticating it, would pass
through an extra local process; this pack's standing rule is that it does not
handle API keys. And the "−74% output" claim needs explaining before it is
believed: input compression is mechanical, but reducing what the model *emits*
by three quarters "with no change to the answers" is a much stronger claim, and
nothing in the README reconciles the two.

# v8.7.2 -- windows-mcp disabled everywhere

**2026-08-30.** Based on v8.7.1 (80b8896). **164 canonical skills**, unchanged.
No new always-on schemas.

## What happened

The `windows` profile (windows-mcp 0.8.5, 20 tools, 22,088 bytes, ~5,522
tokens/turn measured 2026-08-27) was enabled machine-wide on 2026-08-29 via
`Set-McpProfile.ps1 -Enable windows -Global`. That was within the pack's rules
-- the profile ships off by default with no detect markers, and a human turned
it on deliberately. It was turned back off on 2026-08-30 for a reason the pack
could not have known on the 27th: every provider it was wired onto now ships
native desktop control.

- **Hermes**: built-in `computer_use` toolset (background-first, SOM + AX).
- **Claude Code / Cowork**: Anthropic's computer use; docs state screen control
  is reserved for what nothing else can reach.
- **Codex app**: OpenAI's April 2026 update ships computer use on macOS *and*
  Windows.

Grok does not load MCP servers at all (`mcps=false`). The one machine where
windows-mcp added a real capability had none of these hosts.

## The numbers

At ~5,522 tokens per turn per provider, a session of ~120 turns on all three
carried roughly 2M duplicated schema tokens. After the disable: zero. The
profile was never the wrong shape -- measuring before shipping, off by default,
no detect markers -- the enable decision simply aged out in one day.

## What changed

- Live configs reverted: Hermes `config.yaml` `enabled: false`; Codex
  `config.toml` block commented out with a re-enable note; Claude
  `.claude.json` entry removed.
- `PROFILES.json` windows profile `why`/`detect_note` updated to record the
  decision so the next operator reads why it is off before enabling it.
- Version bump to 8.7.2 across every file `check_versions.py` reads.

Re-enable anytime: `TOOLS\Set-McpProfile.ps1 -Enable windows -Global`.

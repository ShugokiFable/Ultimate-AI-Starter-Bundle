# v7.9.9.2 — Fresh-machine installer hotfix

**2026-08-23.** Based on v7.9.9.1.

Skill inventory unchanged: 146 canonical skills per AI shipped.


Installer hotfix. Register-MCP.ps1 threw under Windows PowerShell 5.1 whenever
a provider had NO prior skyrim-forge registration: `mcp remove ... 2>$null`
turns the harmless "not found" stderr into a terminating error under Stop
preference. Every fresh machine with claude/grok/codex CLIs hit this at the
Forge step (INSTALL FAILED, exit 1). Fix: merge streams (`2>&1`) at all three
remove sites. Found by running the real AIO installer end-to-end against the
post-v7.9.9.1 dormant-MCP machine state.

## Follow-up (same day): headroom `--user` vs venv-first PATH

The full-AIO verification pass exposed a second installer defect in the same
family: the headroom component's python probe accepted any interpreter that
answered `pip --version`, including a **virtualenv** python exported onto PATH
(Hermes desktop does this). A venv cannot `pip --user install`, so the
component recorded `status=failed` and the fail-closed installed-state doctor
killed an otherwise-complete install. The probe now skips interpreters whose
`sys.prefix != sys.base_prefix` (and requires real pip exit codes), falling
through to `py`/`python3`. Proven by a full `INSTALL-V7-AIO.ps1` run:
INSTALL COMPLETE, zero failed components.

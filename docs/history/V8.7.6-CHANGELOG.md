# v8.7.6 -- provider and profile convergence

**2026-08-31.** Based on v8.7.5. **167 canonical skills**; no new always-on
MCP schemas.

## Fixed

The catalog and project profiles had become separate version authorities.
Chrome DevTools, shadcn, Blender MCP and Unity MCP were current in the catalog
but stale in their profile commands. Every versioned profile server now names
its catalog component, and a release contract rejects any future disagreement.
The corrected profile pins are Chrome DevTools 1.8.0, shadcn 4.19.0, Blender
MCP 1.9.0 and Unity MCP 0.90.0. Playwright's existing 0.0.79 command is now
bound explicitly as well.

Blender MCP 1.9.0 passed a real initialize/tools-list exchange with 28 tools
and 29,154 schema bytes, about 7,288 tokens per enabled turn. The same probe
showed that an unconfigured server posts an anonymous startup event before
Blender connects. Upstream supports `BLENDER_MCP_DISABLE_TELEMETRY=true`; the
shared MCP config writer now carries literal non-secret server policy into
provider configs, and a repeated probe logged the opt-out with no HTTP request.
The profile stays project-scoped and off until Blender work actually needs it.

RTK's documentation had drifted from the bundle's own measurements. Its
automatic rewrite table still captures the known-bad compound `find` path,
while deliberate `rtk git`, `rtk err` and `rtk test` calls retain the useful
parts. The catalog now records an off hook policy, the installer and current
README no longer print initialization commands, and the doctor reports an
enabled Hermes `rtk-rewrite` plugin instead of silently accepting the drift.
The existing backup-and-rollback profile migration also removes it from every
managed profile's enabled list, parks it under disabled, and verifies both
sides before accepting the write. The live upgrade proof also caught a parser
bug: Hermes' JSON plugin array was being cast to one space-joined string, so
every exact membership check missed. It now remains an actual string array.

A live `-SkillsOnly -SkipNativePlugins` upgrade exposed the mirror image on
Claude and Codex: syncing skills recreated 20 canonical copies beside the 20
skills their existing native plugins already served. The skip path now reads
only the providers' current ownership registries and backup-removes byte-exact
canonical copies. It never invokes an install, update, remove or marketplace
command, so skipping plugin mutation no longer means accepting index bloat.

The final real MCP probe found a separate verifier defect, not broken servers:
current Hermes YAML writes block-list arguments at four spaces, while the
handshake reader accepted only six. It therefore launched Headroom without
`mcp serve`, GitHub without `stdio`, and Context7 without its package argument.
The constrained reader now accepts both valid shapes and the real probes are
run again after the fix.

The same probe also ignored provider enablement. Codex's native list marked
`cua_repl`, Roblox Studio and RobloxForge disabled, but the verifier launched
all three; Claude and Grok similarly appeared to pay for parked game servers.
JSON `enabled`/`disabled` and TOML `enabled = false` now govern discovery before
any process starts, so both runtime proof and schema totals describe the
session the provider actually creates.

Fresh Hermes templates now carry stable runtime config schema 39. This is a
schema-only convergence update: model routing, compression, memory, telemetry
and other personal choices remain user-owned. Windows MCP remains available
but off by default because its measured ~5,522-token standing cost duplicates
native desktop control for the user's primary providers.

## Regression coverage

- Static non-secret server environment values survive both resolver and TOML
  provider-writing paths.
- Versioned project-profile package pins must equal their catalog versions.
- Blender's telemetry opt-out must be executable configuration, not prose.
- RTK's off policy must agree across catalog, installer, current README and
  installed-state doctor.
- Both shipped Hermes templates must match the schema declared by the catalog.

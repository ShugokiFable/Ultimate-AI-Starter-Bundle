# Ultimate AI Starter Bundle — v6.8.1

Date: 2026-08-15
Base: v6.8.0

v6.8.0 claimed the completeness gate was installed on five providers. It was
installed on **two**. This release makes the claim true, by using each
provider's real mechanism instead of one assumed shape.

---

## What was actually wrong

v6.8.0 dropped the same JSON into `~/.<provider>/hooks/` for everyone. That is
correct for Grok and nothing else. Verified per provider against its own docs or
CLI rather than by assumption:

| Provider | v6.8.0 | Reality | v6.8.1 |
|---|---|---|---|
| **Claude** | worked | `settings.json` `hooks` key | unchanged |
| **Grok** | worked | `~/.grok/hooks/*.json`, always trusted | unchanged |
| **Codex** | inert file | Loads hooks from **plugins**; each needs a `trusted_hash` in `[hooks.state]` | installed as a local-marketplace plugin |
| **Hermes** | inert file | `hooks:` block in config.yaml, events `pre_tool_call` / `pre_verify` | wired via its real config |
| **Kimi** | inert file | **No hook or plugin system at all** — skills and MCP only | file removed, documented |

The inert files are deleted on upgrade. A hook that is never read is worse than
no hook, because it looks installed.

## Three traps found while fixing it, each worth keeping

**Hermes does not use the path its own documentation gives.** The docs say
`~/.hermes/config.yaml`; the resolved path honours `HERMES_HOME`, which pointed
at `%LOCALAPPDATA%\hermes`. Writing to the documented path produced a file
Hermes never read, while looking perfectly installed. The installer now asks
`hermes config path` and merges with PyYAML rather than appending text to a
config that already held real settings.

**A Windows path inside a double-quoted YAML scalar is invalid YAML.**
`"C:\Users\..."` makes the backslash sequences bad escapes, the whole document
fails to parse, and Hermes silently reports zero hooks. Paths are emitted with
forward slashes, which Windows accepts and which survive both YAML quoting and
Hermes's `shlex.split`.

**`Copy-Item -LiteralPath` does not expand wildcards.** The Codex plugin was
registered in `config.toml` while its marketplace directory sat empty — a plugin
pointing at nothing. Now `-Path`, with the file count checked afterwards.

## Also

- **Hermes gained the three MCP servers** (context7, sequential-thinking,
  github). It was missing from the v6.8.0 target map entirely. Registered
  through `hermes mcp add`, which connects and discovers tools, so a failure
  means the server genuinely does not work rather than a config key being wrong.
  All three verified enabled: 2, 1 and 26 tools respectively.

## What still needs your hands

Two consent gates, both deliberate, neither safe for an installer to forge:

- **Codex** shows a one-time trust prompt for the plugin's hooks. Approve it.
- **Hermes** requires first-use consent per `(event, command)` pair. Run
  `hermes --accept-hooks` once, or approve at the prompt. `hermes hooks doctor`
  reports `not allowlisted` until you do, and the hooks will not fire.

Forging either would mean writing a security consent record on your behalf.

# V7.9.1 — one repository

*2026-08-20*

Skyrim Forge is developed in this repository now, at `BUNDLED-TOOLS/skyrim-forge`.
There is no separate SkyrimForge release, and there is no Forge ZIP in
`BUNDLED-TOOLS/offline`.

## Windows installer follow-up

- Same-version embedded Forge hotfixes are content-authoritative. `Install-SkyrimForge.ps1` no longer treats matching `VERSION.txt` values as proof the live Forge code is current; it compares the bundled and installed Forge manifests and SHA-256 verifies every shipped file before deciding to skip a refresh. This fixes the case where v7.9.1 contained a corrected `Register-MCP.ps1` but the existing 6.0.0 install kept executing its stale copy. User state (`.venv`, `Workspaces`, `REPORTS`, local `config.toml`) remains preserved across the staged refresh.
- Provider skill synchronization is now based on content, not file-copy metadata. Deterministic release ZIPs reuse fixed timestamps, and the v8/v7.9.1 `release-checklist` files were the same length with the same timestamp despite different bytes. Each bundle-owned skill now uses stage → SHA-256 verify → directory swap → SHA-256 verify. This removes metadata classification from correctness entirely.
- The AIO is the sole writer of bundle-owned `skyrim-forge/SKILL.md`. Forge's bundle wrapper now refreshes only the per-machine `INSTALLATION.json` descriptor and provider MCP registration; it does not replace the bundle's skill. The embedded Forge integration copy is still byte-identical for standalone Forge use.
- Forge's Windows installer captures verbose checked-command output, prints a start marker before each long check, and prints success with elapsed seconds. Full child output is preserved only when a checked command fails, so `self-test`/`config-show`/`doctor` no longer look frozen or dump pages of JSON.
- The root Windows pack gate executes `TESTS/Test-ProviderSkillSync.ps1`, which reproduces the same-name/same-size/same-time/different-bytes stale-file case and proves the production sync updates the hash, removes stale files inside a bundle-owned skill, and preserves unrelated user skills.
- Fixed a Windows PowerShell 5.1 doctor failure caused by literal `\n` edit debris commenting out the `$providerHome` assignment before `Join-Path`. The doctor now validates provider-home resolution explicitly.
- Removed the hidden interactive Hermes `mcp add` automation. Forge MCP registration now uses Hermes' own config loader/saver and a visible, bounded connection test with a 45-second outer timeout and progress every five seconds.
- The release test suite now rejects the accidentally chosen next-major bundle label anywhere in shipped text or filenames. The bundle release is 7.9.1 throughout; Skyrim Forge keeps its independent internal component version.

## Why the split had to go

7.9.0 shipped a fix for this, in `TOOLS/Install-SkyrimForge.ps1`:

```powershell
if (-not $contract.compatible) { throw "Forge reports incompatible bundle contract..." }
```

Forge has never emitted a `compatible` field. `-not $null` is `$true`, so that
line threw on **every** run, and `INSTALL-V7-AIO.ps1` aborted the entire
all-in-one install on the non-zero exit. A fresh Windows install of 7.8.0 could
not complete, with 16/16 contract tests, a 10-section pack gate and a full
manifest verification all green over it.

The fix was correct and the diagnosis was incomplete. The reason no test caught
it is that the installer and the code answering it lived in **two repositories**:
two files that had to agree, released on two schedules, with no single commit
that could test both. Fixing the field without fixing that leaves the next
version of the same bug in place.

So the repositories are merged. One commit can now prove both halves agree, and
the CI job that does exactly that — `forge-bundle-install` — runs the real
installer against the real subtree on a machine with nothing on it. That job
could not have existed before.

## What changed

### Forge is source, not a payload

`BUNDLED-TOOLS/offline/Skyrim-Forge-*.zip` is gone. `Install-SkyrimForge.ps1`
copies `BUNDLED-TOOLS/skyrim-forge` directly, so what installs is whatever this
commit contains. No archive to build, no archive hash to record, no archive
version that can disagree with the installer reading it.

Both release variants carry it in full. Core drops every *third-party* offline
payload as before; Forge was never one of those and is no longer described as
one.

### An upgrade no longer deletes your mod work

The 7.9.0 installer replaced the install directory wholesale: move the old one
aside, move the new one in, delete the old one. Job staging defaults to
`<install root>\Workspaces`, so that sequence deleted the user's workspaces on
every version change. `Workspaces`, `.venv`, `REPORTS` and a local `config.toml`
now move across into the staged tree before the swap.

This was found by reading the staging code while converting it from
zip-extraction to a directory copy. It was never reported, and nothing tested
it.

### `-ForgeRoot`

`INSTALL-V7-AIO.ps1 -ForgeRoot 'S:\Apps\Skyrim Tools\Skyrim-Forge'` puts Forge
next to xEdit and friends instead of under `%LOCALAPPDATA%`. It names the
install directory itself, exactly as `SKYRIM_FORGE_ROOT` does; pointed at a
shared tools folder that already holds other files it refuses rather than
unpacking Forge over them. The LOCALAPPDATA default stays,
because it needs no admin rights and assumes no drive letter, but nobody should
have to discover an environment variable to say where their tools live.

An explicitly named root is created if absent — it is a decision, not a guess. A
stale `SKYRIM_FORGE_ROOT` pointing at nothing still is not.

### `forge bundle-contract` is removed (Forge 6.0.0)

It negotiated a supported bundle version range. Shipping from one repository in
one commit, that check cannot fail for a real reason — but it can go stale and
start rejecting the very pack it lives inside, which is one edit away from the
bug above. It carried a hard next-major ceiling; keeping that cross-product handshake after the merge would only leave a stale range that can later reject the bundle it ships inside.

The installer runs `forge doctor` instead, which can still genuinely fail:
broken virtualenv, missing native helper, unreadable config, unresolvable
workspace. `test_forge_health_check_reads_fields_forge_emits` parses `doctor()`
out of `skyrim_forge/environment.py` with `ast` and fails if the installer reads
a field it does not return — the same gate as before, aimed at something that
still exists.

### CI

The root workflow gained the five jobs that used to live in the SkyrimForge
repository, plus the end-to-end install job:

| job | what it proves |
|---|---|
| `forge-python` | 3.11 / 3.13 / 3.14 × ubuntu / windows |
| `forge-native` | gofmt, vet, tests, race, pinned Go 1.23.2 |
| `forge-repository-validation` | reproducible native build, full publication gate |
| `forge-windows-installer` | venv repair, config migration, skill install ×2, MCP bridges |
| `forge-bundle-install` | the bundle installs Forge from this tree, end to end |

No `paths:` filter. A required check that only sometimes runs eventually blocks
everything, and the point of the merge is that one commit proves both halves.

`codeql.yml` and `dependabot.yml` came across too, repointed at
`BUNDLED-TOOLS/skyrim-forge/writer/native-go`.

### One launcher, durable failures

`START-HERE.bat` is the canonical local double-click entry. The old
`INSTALL-V7-AIO.bat` remains only as a compatibility alias, so launcher
behavior cannot drift between two copies. A failed install no longer vanishes
as a one-frame red console: the window stays open for interactive launches and
the PowerShell installer writes a timestamped transcript plus stable
`INSTALL-LAST.log` and `INSTALL-FAILED.txt` diagnostics under
`%LOCALAPPDATA%\Ultimate-AI-Starter-Bundle\logs`.

### Provider helper calls are closed over their definitions

A real Windows run reached Kimi plugin installation and stopped with
`Install-V5KimiPlugin` not recognized. The merge had omitted two live helpers
from `TOOLS/V7-Common.ps1`: `Install-V5KimiPlugin` and
`Restore-V5HermesPluginScan`. The first was the observed crash; the second would
have become the next crash after fixing only Kimi. Both known-good helper
implementations are restored.

The existing static helper test had a blind spot: it scanned only PowerShell
scripts under `TOOLS` and `TESTS`, while the production caller is the root
`INSTALL-V7-AIO.ps1`. The gate now scans root PowerShell entrypoints too and
proves every `*-V5*` helper call resolves either locally or in `V7-Common.ps1`.

### Embedded Forge tooling follows the enclosing repository

Forge no longer owns a subtree `.github`, so its validator and native rebuild
helper walk upward to the enclosing repository's workflow when resolving the
pinned Go toolchain. This keeps the merged source independently verifiable
without reintroducing dead workflow files inside the subtree.

### Portable executable mode

The release builder explicitly records the published Linux Forge native helper
as POSIX `0755`. ZIPs created on Windows otherwise lose that bit, producing an
archive whose hashes are correct but whose Linux validation fails with
`PermissionError` after extraction.

Forge's own `.github/` is deleted rather than carried: GitHub reads
`.github/workflows` only from a repository root, so those files would look live
and never run — dead config that reads as live is the failure class this release
is about. Two Forge tests and its version gate opened those paths directly; they
walk up to the checkout root now, via `tests/_workflows.py`.

## Final Windows run fixes

The first real 7.9.1 Windows run got all providers and Forge 6.0.0 installed,
then the final installed-state doctor crashed before it could check anything.
PowerShell variable names are case-insensitive, and the doctor assigned `$home`;
that is the read-only automatic `$HOME` variable on Windows PowerShell 5.1. The
local variable is now `$providerHome`, with a release regression for the exact
collision.

That crash was masking another guaranteed failure. The doctor still invoked the
Forge 5.x `bundle-contract` command even though Forge 6.0.0 intentionally removed
it after the repository merge. The final doctor now runs `forge doctor`, parses
the JSON, and requires both `result: PASS` and `read_only_ready: true`, matching
the bundle-managed Forge installer.

The parent installer now captures the child doctor's combined output and replays
it before throwing. `Start-Transcript` does not reliably capture direct output
from a child `powershell.exe`, which is why the durable log originally contained
only `Final installed-state doctor failed with exit code 1` while the console
had the useful `$HOME` exception. Future doctor failures keep their root cause in
`INSTALL-LAST.log` and the failure summary.

The canonical `skyrim-forge` skill was stale too: it still presented Forge as
5.x, required the removed 5.2 bundle handshake, and described a version-stamped
`Skyrim-Forge-<version>` live layout. It now describes Forge 6.x, the versionless
`SKYRIM_FORGE_ROOT` install and the `forge doctor` health contract, then fans out
to all five providers.

## Known limits

- Cloning this repository on Windows needs `git config --global core.longpaths true`.
  Paths under `_V7-CANONICAL-SKILLS` already exceeded 260 characters before the
  Forge subtree was added.
- The three original pack jobs use floating action refs (`actions/checkout@v4`)
  while the five Forge jobs are SHA-pinned. Left as-is deliberately: changing
  the working jobs was not worth the risk in the same release that restructures
  the repository.
- `test_line_endings_match_their_declared_attribute` in the Forge suite now
  skips. It only runs when a `.gitattributes` is present in the subtree, and the
  repository-wide `* -text` replaced it. Byte fidelity is still gated, by
  `MANIFEST.json` over the whole tree.

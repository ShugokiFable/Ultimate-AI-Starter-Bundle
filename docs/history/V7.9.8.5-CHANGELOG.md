# v7.9.8.5 — cbm field lessons: the dashboard bug was never the user's fault

**2026-08-22.** Based on v7.9.8.

A point release. One skill gained a working-fix section from production use on
Windows, and the version gate learned to accept point releases at all.

---

## The field session that produced this release

A maintenance pass on the live `codebase-memory-mcp` install (v0.10.8, latest
at the time) turned into evidence the pack's own skill did not have:

- **The zero-tiles bug is upstream and confirmed, not user error.**
  `DeusData/codebase-memory-mcp` issue **#1663**: since v0.10.5 the web UI's
  RPC allowlist admits only `list_projects` and `get_code_snippet`, but the SPA
  calls `get_graph_schema` for its NODES/EDGES tiles and per-project language
  previews — every call is rejected with "UI RPC method is not allowed" while
  `/api/project-health` keeps serving correct numbers. The maintainer
  confirmed it in code ("deterministic high-priority UI regression"); it
  remained unfixed in 0.10.8. The reporter had been told by another assistant
  that "the new update broke it"; the update *did* break it — deterministically,
  and still had.
- **The workaround is a same-origin companion proxy**, not a fork: serve the
  stock UI through a loopback proxy that also exposes real totals and
  per-project health, because upstream's DNS-rebinding defense rejects any
  foreign-origin page that tries to read those endpoints.
- **Auto-indexing stays vetoed, now with proof:** one MCP handshake from a
  scratch directory indexed the `%TEMP%` folder as its own project within
  seconds. Deliberate indexing with curated `.cbmignore` rules remains the
  discipline.
- **Issue #1764 (idle CPU burn) is NOT what its own root-cause comment says.**
  The maintainer attributed the ~0.6-core-per-idle-client burn to two 10 ms
  maintenance observers walking the Windows file-lock path. A geometric-backoff
  patch of exactly those observers was built from source (MinGW gcc 15.2,
  `-Werror`) and A/B-tested idle against stock 0.10.8: **no improvement** —
  and the burn reproduced only on roughly half of spawns, always a single
  thread. The published root cause does not explain the symptom; do not cite
  it as solved.

## What changed in the pack

- `_V7-CANONICAL-SKILLS/codebase-memory/SKILL.md` (+ all 10 provider copies):
  documented #1663 with the allowlist mechanism, the same-origin-proxy
  workaround shape, the `%TEMP%` auto-index trap, and a warning that #1764's
  accepted root cause failed an A/B repro.
- `.github/scripts/check_versions.py`: version patterns widened from exactly
  three parts to three-or-more (`(?:[0-9]+\.)+[0-9]+`). Without this gate fix
  a 4-part `VERSION.txt` would fail CI with every declaration reading as
  truncated. This release is the first 4-part version; the gate now accepts
  both shapes and still requires exact equality everywhere.

No skills were added or removed; canonical skill count stays 146. No bundled
tool versions changed.

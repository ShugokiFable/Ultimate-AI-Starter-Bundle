# v8.3.0 -- Stop leaving things behind

**2026-08-25.** Based on v8.2.0. 146 canonical skills, unchanged. No new skills
and no new MCP servers.

v8.1.0 decided which servers a machine pays for. v8.2.0 decided how much of each
one. This release deals with what the installer left on the machine on the way
there.

---

## The installer never removed a skill it stopped shipping

It copies `_CANONICAL-SKILLS` into every provider's skills directory. It has
never deleted a skill that left that tree. So a machine installed against v7
still carries the v7 names, forever.

Measured on the maintainer's machine at v8.2.0:

```
.claude/skills   206 entries   (146 canonical)
.codex/skills    226
.grok/skills     226
hermes/skills    247
```

Seven of those extras are skills **this pack retired**, present in three
provider trees -- twenty-one directories, each one loaded and offered to the
agent next to the skill that replaced it:

| still installed | replaced by |
|---|---|
| `skyrim-kid-distribution` | `kid-authoring` |
| `skyrim-spid-distribution` | `spid-authoring` |
| `skyrim-esp` | `skyrim-plugin-authoring` |
| `skyrim-papyrus` | `skyrim-papyrus-modding` |
| `skyrim-mcm` | `skyrim-papyrus-modding` |
| `skyrim-skse` | `skse-plugin-authoring` |
| `skyrim-archive` | `skyrim-assets-pbr` |

That is not clutter. Two skills claim to own KID syntax and **the retired one
documents the older dialect** -- the exact failure mode this pack exists to
prevent, shipped by the pack itself.

`BUNDLED-TOOLS/RETIRED-SKILLS.json` now declares the retired set, derived from
this repository's own history by `TOOLS/generate_retired_skills.py` rather than
hand-maintained, because a hand-maintained list drifts the first time someone
renames a skill and forgets.

## Backups with no ceiling

Every install writes `config.toml.bak-*`, `AGENTS.md.before-soul-*.bak`,
`settings.json.bak-gate-*` and an install log. Nothing ever pruned them:

```
Grok config backups        86 items
Claude settings backups    25
Grok AGENTS backups        17
Claude CLAUDE.md backups   17
Codex config backups       16
UABS install logs          15
...                       ---
TOTAL                     217 items, 2.1 MB
```

Inert, but unbounded -- and 86 backups bury the one someone might actually want
to restore.

## `TOOLS\Clean-StaleState.ps1`

One tool for both, **dry-run by default**:

```
  backup           169 item(s)     1,116 KB
  log               10 item(s)       403 KB
  skill/Claude       7 item(s)        79 KB
  skill/Codex        7 item(s)        79 KB
  skill/Grok         7 item(s)        79 KB
  TOTAL            201 item(s)     1,681 KB

  Nothing was removed. Re-run with -Apply to delete the items above.
```

It runs automatically at the end of every successful install, so a machine
converges on the current tree instead of accumulating every version it has seen.
`-SkipCleanup` opts out.

**Deletion is limited to what this pack created.** Three guards, each with a
contract:

- A retired skill is removed only if its name is in `RETIRED-SKILLS.json` **and
  not in the canonical tree**. A drifted list cannot delete a live skill.
- The directory must contain a `SKILL.md`, so an unrelated folder that happens
  to share a retired name is left alone.
- Backups match the pack's own naming patterns, keeping the newest 3 per family
  and the newest 5 install logs. Log retention is `ValidateRange(1, 200)` -- it
  cannot be set to zero and delete the evidence of the run that deleted it.

Everything else -- plugin-provided skills, the optional Other-Games mega-pack,
a user's own files -- is reported, never touched. It runs after the final
doctor, so a failed install keeps every log and backup for diagnosis.

## Routing now knows what a tool costs

The `ai-tooling-stack` cheat-sheet routed on **capability only**, so a free CLI
and a 41,768-token-per-turn MCP server looked equally attractive for a job they
could both do.

| tool | surface | standing cost |
|---|---|---|
| **Skyrim Forge** | 52 subcommands, **CLI** | **0 tokens** |
| Skyrim Forge as MCP | the same 52 tools | ~4,372 tokens/turn |
| **Spooky's AutoMod** | CLI with `--json` | **0 tokens** |
| **houseCARL** | 45 tools, **MCP only -- no CLI** | ~41,768 tokens/turn |

Every Forge MCP tool has a CLI twin -- `forge plugin-build`,
`forge record-query`, `forge papyrus-compile`, `forge fomod-build`,
`forge release-build` -- verified against `forge --help` on the installed 6.0.0.
So the rule is: **Forge's CLI first, houseCARL only for what wins in the LIVE
load order**, which nothing else can answer.

### The correction that makes this work

The obvious version of this idea -- *prefer the cheaper MCP server* -- **saves
nothing**, and the skill now says so. An MCP server's schemas are in context on
every turn from the moment it is registered, whether or not anything calls it.
Preferring around a registered server does not reduce that by one token. The
saving comes from **not registering** it, or from registering fewer of its
tools; never from choosing differently at call time.

For Hermes, where MCP is billed on the user's own key, that is what
`-SkyrimToolset` is for (v8.2.0).

## Encoding: the gate was watching four file types

Section 3 checked `*.ps1`, `*.psm1`, `*.bat`, `*.cmd`. Everything the pack
**copies onto a machine** was unguarded -- and one of those files has already
been corrupted this way. From `README.md`, still describing v7.5.6:

> em dashes in `AIO-INSTRUCTION.txt` into `\xe2€"` ... v7.5.6 cleaned the files

Nothing was watching it afterwards. Five deployed artifacts carried non-ASCII
typography and are now pure ASCII:

- `COPY-TO-YOUR-WORKSPACE/AIO-INSTRUCTION.txt` (the one with the history)
- `3-PREAMBLES/MANUAL-PASTE.txt` (the user pastes it by hand)
- `1-TAILORED-PROVIDER-TREES/Hermes/config.yaml` and its twin (written into the
  Hermes home and re-saved by Hermes' own YAML writer)
- `_CANONICAL-SKILLS/housecarl/.claude-plugin/plugin.json`

The gate now checks every deployed artifact by name, plus a repository-wide
sweep for `U+FFFD` -- a replacement character is decoding that has *already*
failed, never intent. Falsified before shipping: appending one em dash to
`BOOTSTRAP.txt` fails the gate.

### What was deliberately NOT converted

2,405 shipped files contain non-ASCII. Nearly all of it is intentional: check
marks and arrows in skill prose, box drawing in banners, CJK in a vendored
skill. Folding those would be thousands of files of churn that destroys meaning
to fix nothing -- a `.md` file read by an agent or rendered on GitHub has no
encoding problem. `TOOLS/build_release.py` keeps its omega, which is a
deliberate fixture proving the builder survives a non-ASCII temp path, and
`audit_skills.py` keeps the mojibake sequences it exists to detect.

The rule the gate encodes is narrower and true: **anything this pack writes onto
a machine is ASCII.**

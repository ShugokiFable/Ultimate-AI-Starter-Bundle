# v8.6.2 -- Count it, don't infer it

**2026-08-26.** Based on v8.6.1. 160 canonical skills, unchanged. Four bugs --
three in the same failure family, a number that was computed instead of read
-- and one MCP server added because its cost was measured rather than assumed.

---

## The doctor was wrong about the Codex skills index, by 122 entries

Codex renders its skills index into a fixed block and splits the budget across
every entry, so entry COUNT is what decides how much of each description
survives. Reporting that count wrong is not a cosmetic error -- the report also
tells the user how bad their descriptions are.

v8.4.0 fixed an undercount by having the doctor walk `plugins\cache`. That
over-corrected. Codex indexes only the plugins `config.toml` **enables**; the
cache also holds:

- marketplaces that were added and never enabled (114 skills here),
- backup copies of upgraded plugins (`plugin-backup-xEwES6`),
- payload directories meant for other tools (ponytail ships an `.openclaw\skills`).

Measured on the maintainer's machine:

| | entries | visible description |
|---|---|---|
| doctor reported | 319 | ~16 chars ("Use when buildin") |
| Codex was actually rendering | **197** | **42 chars** |

The advice attached to that warning -- start deleting plugins -- was being
given to someone whose index was fine.

The doctor now asks Codex. `codex debug prompt-input` emits the exact block the
model receives; the entry count and the description width are **measured** off
it rather than estimated from a curve. The curve survives as the fallback for
when the CLI cannot be asked, and that branch now says out loud that its figure
is an estimate. The fallback also stops walking the whole cache: it enumerates
only the plugins `config.toml` enables (179 vs the true 177 here, against 319
before).

The measured index lands in the JSON report as `codex_skill_index`.

## One broken marketplace silently cost 20 duplicate skills

`codex plugin list --json` refuses to answer at all when **any** configured
marketplace snapshot is unloadable -- including one that has nothing to do with
the plugin being asked about:

```
Error: failed to load configured marketplace snapshot(s):
- `headroom-marketplace` at ...\.tmp/marketplaces\headroom-marketplace:
  marketplace root does not contain a supported manifest
```

The installer read that empty answer as "the native install failed", so it
skipped the dedupe that removes copies a native plugin already owns. Superpowers
and ponytail were installed, enabled, and working -- and their 20 skills were in
the index **twice**, once from the plugin and once from this pack's copies.

The installer now falls back to Codex's own registry (`config.toml`) when the
inventory cannot be read, and says so instead of degrading quietly. Only the
top-level `[plugins."<id>"]` table counts: Codex also writes nested tables such
as `[plugins."browser@openai-bundled".ambient]` with their own `enabled` keys,
and reading those inverts the answer.

The doctor now names duplicates directly, because that is the one index cost
this pack can actually fix.

After the repair, on the same machine: **197 -> 177 entries, 42 -> 54 visible
description chars.** Every skill in the index got 29% more description.

## `-Providers Codex` failed the doctor on a correct machine

`native_plugins` records which skill copies a native plugin legitimately owns,
and the doctor treats a copy that is absent *without* such a record as a fatal
missing skill -- correctly, because that is what a half-finished install looks
like.

The installer wrote that map wholesale at the end of every run, so a
single-provider run erased the record for the four providers it never visited.
Measured: a `-Providers Codex` run after a full install produced **34 doctor
errors** on a machine where nothing was wrong. Records for providers outside
this run are now carried forward.

## A boot-time launcher whose target is gone

Three entries in the Startup folder on the maintainer's machine, all written by
past agent sessions rather than by this pack:

| entry | target |
|---|---|
| `cbm-dashboard-plus.vbs` | a script under the `Skyrim-AI-V5` tools folder -- **the whole tree was gone** |
| `codebase-memory-keepalive.vbs` | present |
| `Hermes_Gateway.vbs` | present, but `"platforms":{}` and two copies running |

The dead one had been failing at every boot for a week. Nothing surfaces that:
it is not an error anyone sees, and Task Manager's Startup tab shows the entry
without saying the target is missing.

The doctor now enumerates the Startup folder and the HKCU `Run` key, keeps the
entries that launch AI tooling, and resolves every path each one needs -- a
`.vbs` launcher names the interpreter AND the script, and it is normally the
second that has gone missing. A live entry is listed; a dead one is a warning.
The result lands in the JSON report as `ai_autostarts`.

`Clean-StaleState.ps1` reports them too, and this is the part with a contract
on it: **it does not delete them.** The rule at the top of that file is that
deletion is limited to what this pack created, and this pack has never written
an autostart. Reporting is the whole job; the fix belongs to whoever made the
entry.

Two measured details worth keeping:

- Bare `chroma` in the match list hits Razer Synapse's RGB autostart
  (`--url-params=apps=synapse,chroma-app`). It is `chroma-mcp` now. A false
  positive in a report someone is meant to act on is a real cost.
- `@($list)` over a `List[object]` whose items carry array-valued properties
  throws `Argument types do not match` on PowerShell 5.1. `.ToArray()` is not a
  style preference there; the other form is a crash.

## context7, on measured cost

`TOOLS/measure_mcp_capability.py` against the pinned `@upstash/context7-mcp@4.0.2`
with the credential environment scrubbed:

```
context7 -- 2 tools, 4870 schema bytes, no credentials

KEYLESS      2  resolve-library-id, query-docs
RATE_LIMITED 0  NEEDS_KEY 0  DEPRECATED 0  UNVERIFIED 0
```

Every advertised tool works with no key. `--api-key` / `CONTEXT7_API_KEY`
exists -- the server's own `--help` documents it -- and raises rate limits
without unlocking a single additional tool.

That makes it the cheapest server this pack ships, at roughly 1,220 tokens per
turn. The comparison that decides it: **firecrawl-mcp is 36,321 bytes for the
same count of usable keyless tools**, which is why this pack refuses to register
firecrawl without a key. Same test, opposite answer, and the number is what
separates them.

It does not overlap `codebase-memory`. That one indexes the symbols and call
graph of the repository you are in; context7 answers about code you did not
write. No tool names collide.

## A dict-shaped `models:` duplicates rather than narrows

From Hermes' own `model_switch.py`:

> List/string shapes remain allowlists for no-key endpoints. To pin a
> dict-shaped catalog, set `discover_models: false`.

`if isinstance(value, dict): return False` -- so a dict `models:` is not read as
an allowlist at all. It merges alongside discovery, and the model picker shows
the entry twice. The tell is that it looks right while LM Studio is idle,
because discovery has nothing to contribute yet, and doubles the moment a model
loads.

`local-model-ops` documents the shape rule, and one thing that only shows up
when you go looking: a stale local model id does not live in one key. On the
maintainer's machine it appeared **six times** -- `model.default`, the
provider's own `model:`, the dict catalog, `model_aliases.local.model`, and both
`moa` aggregators -- and not one of the six matched the id the server was
actually serving. A name that does not resolve fails soft into
`fallback_providers`, so the symptom is "local is slow", never an error.

## Contract

Four new contracts and one rewritten:

- `test_codex_index_is_measured_not_inferred_from_the_plugin_cache`
- `test_codex_plugin_detection_survives_one_broken_marketplace`
- `test_subset_install_keeps_the_other_providers_native_plugin_records`
- `test_dead_autostarts_are_reported_and_never_deleted`
- `test_doctor_counts_every_skill_root_and_never_interpolates` now requires the
  curve to be the fallback rather than the headline, and requires the estimate
  to be labelled as one.

context7 needed no new contract: `test_capability_claims_match_the_measured_record`
already cross-checks every capability record against the catalog, and it was
falsified against context7 specifically to prove that it does.

93 contracts. The autostart contract was falsified with 12 mutations, 12 caught.

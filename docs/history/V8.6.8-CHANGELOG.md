# v8.6.8 -- the advice was stale, and the README was 61% changelog

**2026-08-27.** Based on v8.6.7. **164 canonical skills**, unchanged. A warning
this pack had been giving for several releases turned out to be wrong, a
measured claim was fixed in one file and left rotting in another, and the README
had quietly become mostly changelog.

---

## The rtk warning was wrong

The catalog said, for several releases:

> Do NOT install the Claude Code / Cursor / Gemini shell hooks on native
> Windows: they silently degrade to CLAUDE.md prompt injection.

Re-tested at rtk 0.45.0 on native Windows. The **global** form registers a real
hook:

```
$ rtk init -g --agent claude
RTK hook registered (global).
  Command:   rtk hook claude
  RTK.md:    ...\RTK.md (10 lines)
  CLAUDE.md: @RTK.md reference added
```

`rtk hook claude` is a **PreToolUse hook reading JSON from stdin**. It rewrites
`git status` into `rtk git status` transparently, and the file it leaves behind
is **990 bytes**.

The **non-global** form is the one that degrades, and it says so itself:

```
$ rtk init --agent claude
[rtk] /!\ No hook installed - run `rtk init -g` for automatic token savings
[ok] Added rtk instructions to CLAUDE.md
```

That block is **5,140 bytes** -- roughly 1,400 tokens on every turn, forever,
0.8x the size of this pack's entire AIO preamble, spent asking for savings it
cannot enforce.

So the distinction that matters is `-g`, not the provider. The blanket warning
is gone and the precise one replaces it, in the catalog, the README and the
contract that guards them.

## The rewrite engine, checked rather than assumed

Dry-run through `rtk hook check`:

| command | rewritten to |
|---|---|
| `git status` | `rtk git status` |
| `git diff HEAD~3` | `rtk git diff HEAD~3` |
| `ls -la` | `rtk ls -la` |
| `cat secrets.env` | `rtk read secrets.env` |
| `npm test` | *no rewrite* |
| `curl -s https://api.example.com/...` | *no rewrite* |
| `python manage.py migrate` | *no rewrite* |
| `gh pr view 10 --json body` | *no rewrite* |

`cat` becoming `rtk read` looked like the dangerous one -- a filtered file read
is a wrong answer that looks like a right one. It is not: `rtk read` returned
**byte-identical** output to `cat` on a 60-byte env file and a 67 KB PowerShell
script. Worth testing rather than warning about.

`curl` already passes through untouched, so the pack's long-standing
`exclude_commands = ["curl"]` advice pins behaviour rtk already has rather than
fixing a hazard it does not. It stays, as a pin.

## One fact, two files, one of them fixed

v8.6.6 caught that the rtk savings claim was measured against `git diff HEAD~3`
-- a moving reference whose 97% reads 82.5% today -- and pinned the catalog to
tag ranges.

It did not touch the README, which went on advertising:

| Command | Raw | Through rtk | Saved |
|---|---|---|---|
| `git diff HEAD~3` | 2,010,426 B | 71,268 B | **97%** |

Both now carry the same pinned table and the same honest range, **25% to 95%**,
because a single headline number for a corpus-dependent filter is not honest.

A contract now asserts no moving reference appears in that table again. It is
scoped to the table rows rather than the section: the prose beside it names
`HEAD~3` on purpose, to explain why the refs are pinned, and a blanket ban would
have deleted the explanation along with the defect. The first version of that
assertion did exactly that, and failed on its own text.

## `-WithRtk`

rtk is now one flag, like claude-mem:

```powershell
.\INSTALL-AIO.ps1 -WithRtk
```

The installer fetches the binary and then **prints** the hook command for each
provider it found, rather than running it:

```
==> rtk is installed - one command left, and it is yours to run
     rtk init -g --agent claude
     Grok is unsupported by rtk; Codex has no rtk hook.
     rtk DISCARDS what it filters: no archive, no retrieval.
```

### Why it is still not default

Three reasons, written down so the question stops recurring:

1. **rtk discards.** On what it filters there is no archive and no retrieval:
   87% saved is 87% gone. If an agent needs the full diff, it cannot get it
   back. OMNI keeps a retrievable copy below its 64 KB cap; rtk keeps nothing.
2. **The hook rewrites every shell command** on the machine, and registering it
   patches the provider's `settings.json`.
3. `installed != enabled` is this pack's whole thesis. A tool that silently
   rewrites tool output is exactly what a human should switch on knowingly.

Installing the binary alone would have been the worst of both: a download that
saves nothing.

## The README had two changelogs, and one was thirty releases stale

Measured before the edit: **61.5% of the README was version history**.

| section | lines | bytes |
|---|---|---|
| `What's new` | 506 | 30,480 |
| `Version` | 86 | 14,202 |
| everything else | 571 | 27,913 |

`What's new` was the worse half. It stood over a list that began at **v8.0.4**
while the pack shipped through 8.6.x, under the words *"Recent releases first"*.
Thirty releases of not-recent. `Version` below it was current and correct, so
the README was disagreeing with itself about what the newest release was.

`What's new` is now a pointer. `Version` keeps the current 8.6 line, eight
paragraphs, and points at the rest. **1,196 lines became 635**, 72,595 bytes
became 39,746, and nothing was lost: `CHANGELOG.md` carries all 86 entries and
`docs/history/` has 92 long-form write-ups.

Every string a contract requires -- the skill count, the 65,536 context floor,
the Forge version, `rtk init -g`, `rtk gain` -- was asserted present outside the
cut regions before a byte was removed.

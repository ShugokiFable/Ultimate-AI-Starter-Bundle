# v7.7.8 - Skill tree dedupe: dead modules pruned, KID/SPID owners consolidated

The canonical skill tree shipped five dead module docs (`skyrim-archive`,
`skyrim-esp`, `skyrim-mcm`, `skyrim-papyrus`, `skyrim-skse`) whose only file
was a lowercase `skill.md`. No agent loader reads `skill.md` - every loader
looks for `SKILL.md` - so those skills were invisible, yet the installer
still copied them into all five provider homes as dead weight. It also
shipped two terse pack twins (`skyrim-kid-distribution`,
`skyrim-spid-distribution`) that duplicated the grammar owned by
`kid-authoring` / `spid-authoring`, so agents were routed to two skills for
one job and nobody knew which was canonical.

Fix:

- Pruned the five dead dirs and the two twins from `_V7-CANONICAL-SKILLS`;
  re-fanned all five provider trees (486 files each); regenerated
  `MANIFEST.json` (3763 files, 182 MB).
- Nothing lost: `validate_kid.py`, `validate_spid.py`, and the pinned
  KID 4.0.6 / SPID 7.3.1 authority references moved into `kid-authoring` /
  `spid-authoring`, which now carry their own `## Validation` section.
- Routers repointed: `skyrim-tool-router`, `skyrim-frameworks-index`,
  `skyrim-runtime-patching`, `ai-tooling-stack`, `spookys-automod-toolkit`.
- Root cause: `TOOLS/install_live_skills.py` now skips canonical dirs
  without a `SKILL.md`, so a dead dir can never propagate to a provider
  home again.
- `audit_skills.py`: PASS (0 fail).

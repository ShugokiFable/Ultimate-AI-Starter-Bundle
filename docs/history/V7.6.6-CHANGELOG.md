# v7.6.6 — dead trees, dead models, and a live MCP health sweep

Operator-ordered tidy-up release: the pack had grown parallel structures that
only existed to drift apart, plus a prompt library carrying
retired-generation material. Also the result of a full six-agent MCP health
sweep done the same evening.

## The duplicate skill tree is gone

`2-OPTIONAL-SHARED-GENERIC/` held five provider trees that differed from
`1-RECOMMENDED-SEPARATE-TAILORED/` in just 80 files out of ~2,500 — and the
installer has only ever read the tailored tree (`INSTALL-V7-AIO.ps1` lines
222/309). 40 MB of near-duplicate content whose only real effect was making
the pack harder to keep track of, which is the operator's words and the point.

This is also the exact failure `TOOLS/fanout_providers.py` was built to
prevent: v5 kept five hand-maintained copies and ended up with a corrected
skill live and a stale one in the bundle. Two generated trees is the same
trap with extra steps. The fanout tool now generates the tailored family
only, the pack gate checks that family only, and the layout docs match.

## The housecarl `.mcp.json` trap

Every provider copy of the housecarl skill shipped an inert `.mcp.json`
pointing at `${CLAUDE_PLUGIN_ROOT}/server/housecarl-mcp.exe` — a path that
resolves nowhere, since the skill package contains no `server/`. Nothing
loads it today; the day any host starts honouring in-skill MCP templates, it
becomes a broken server entry on five machines at once. Deleted from all 11
copies. Housecarl MCP is wired by the installer into each agent's real
config — verified working in the sweep below.

## Six-agent MCP health sweep

Every configured server entry was resolved to its command and checked against
the disk: **42 servers across 6 agents, all launchable.** Findings:

- **Broken, fixed:** Skyrim-Forge's venv `skyrim_forge_local.pth` pointed at
  `Skyrim-Forge-5.1.3`, deleted by the 5.1.4 upgrade — the upgrader never
  rewrites the `.pth`. Hermes had been parking `skyrim-forge` on every start
  ("No module named skyrim_forge"). Repointed at 5.1.4; module imports.
- **Advisory:** the machine PATH still references an uninstalled
  `C:\Program Files\nodejs`. npx resolves via `hermes\node` today; if Hermes
  is ever removed, every npx-based server in all five other agents breaks at
  once. Not touched — registry PATH edits are the operator's call.
- Hermes' empty `plugins/` folder is not a fault: it is the user-plugin drop
  folder; bundled plugins (`disk-cleanup` etc.) live inside the package, and
  `hermes plugins list` shows them enabled.
- Hermes config edits require a **full** restart of the desktop app — the
  backend reads `config.yaml` at start and rewrites it on exit, so edits made
  while it runs are neither loaded nor preserved.

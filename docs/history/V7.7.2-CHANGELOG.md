# v7.7.2 - the Grok MCP cliff guard

`Ensure-Headroom-Grok.ps1` used to unconditionally register headroom into
`~/.grok/config.toml`. On this machine that meant 7 configured servers; with
claude-mem's `mcp-search` plugin server loading on top, Grok hit the
documented 8-running-server cliff and stopped replying (mcp_wait_ms ~34,900,
"process never exits").

## What changed

- **The script now guards the cliff.** It counts `[mcp_servers.*]` in
  `~/.grok/config.toml` and refuses to register when the total would put Grok
  at 8 running: 7 configured with the plugin server disabled, 6 while it
  loads. It names the fix instead of silently skipping.
- **The plugin server is disabled for Grok.** `grok mcp disable mcp-search`
  persists to `disabled_mcp_servers` in `~/.grok/config.toml` and removes the
  free-rider slot without touching Claude Code, where claude-mem's hooks and
  mcp-search keep working normally.
- **Verified end to end.** A fresh Grok session with 7 configured servers
  made a real `tools/call` (`skyrim-forge__forge_version` -> 5.1.5) and
  completed normally. The 8-server wedge reproduces only past the guard.

# v8.1.0 — One click means one click

**2026-08-25.** Based on v8.0.4. 146 canonical skills, unchanged, mirrored
across five provider trees. No new skills and no new always-on MCP.

The pack's own rule is *installed ≠ enabled*. This release applies it to the
installer itself: a plain double-click now configures the AI tools you actually
have, instead of assuming five and fetching the rest.

Plus the Hermes native-profile work, which landed as a separate track.

---

## A one-click install was installing things nobody asked for

Through v8.0.4, `-Providers` defaulted to all five and `Ensure-Provider-CLIs.ps1`
then downloaded every missing one from its vendor script. So on a machine with
only Claude Code, `START-HERE.bat` finished by installing Codex, Grok, Kimi and
Hermes — four CLIs, four auth prompts, four sets of config files, none of them
requested. Uninstall one and the next run brought it back.

A plain run now detects and wires what is installed:

```
Mode=OnlineLatest  Providers=Claude,Grok,Hermes [auto-detected]
Not installed here, so not touched: Codex, Kimi  (add them with -AllProviders)
```

Three deliberate details:

- **Detection is executable presence, not a config folder.** `~/.kimi-code`
  survives an uninstall — it holds `AGENTS.md` backups — and treating it as
  evidence would re-wire a provider that was deliberately removed. Only a
  resolvable `kimi.exe` counts.
- **An empty machine still gets everything.** Nothing detected means a genuinely
  fresh profile, where installing all five is the only outcome that leaves the
  box usable. `-AllProviders` forces it on any machine.
- **`ValidateSet` had to go.** `START-HERE.bat` forwards through
  `powershell -File`, which collapses `-Providers Grok,Claude` into one string;
  `ValidateSet` rejected it. The comma form is split before validating now, so
  the documented syntax works from the launcher people actually use.

The detector is exercised against a real filesystem — throwaway
`USERPROFILE`/`LOCALAPPDATA`, planted executables, emptied `PATH` so the build
machine's own installs cannot answer for the sandbox — in
`TESTS\Test-ProviderDetection.ps1`, chained into the pack gate. Reading the
installer's source and agreeing with it is not a test.

## claude-mem is opt-in

Every other component installs unattended. claude-mem installs the Bun runtime,
starts a background worker daemon, and needs a Claude Code restart before its
tools appear. Good software; three surprises for one double-click.

It moved behind `-WithClaudeMem`. The Bun install was already gated on
claude-mem being requested, so the default path stops pulling a second
JavaScript runtime onto the machine as a side effect.

## One launcher, not two

`INSTALL-V8-AIO.bat` contained exactly one instruction:

```bat
call "%~dp0START-HERE.bat" %*
```

A second name for one action, and a sixth place `check_versions.py` forced the
version to be restated by hand every release. Deleted. Two `.bat` files remain
and they do different things: `START-HERE.bat` installs from this folder,
`INSTALL-REMOTE.bat` downloads the release first. Both README and START-HERE.txt
now say which is which in a table, because "what are the other two bats for?"
is a fair question that the folder listing was answering badly.

`Future thoughts.txt` — one unreferenced line in the repo root — is gone too.
Its content was a real design rule, so it is now stated in the README where it
governs something: *bundle defaults optimize for a new user's reliability; the
per-machine result optimizes for the capabilities actually present on that
machine.* That is precisely what provider auto-detection implements.

## Hermes native profiles

Hermes 0.20.5 has first-class named profiles, each with its own home and config.
The pack's architecture still said "Hermes has one config and no profiles",
which had been false for a while. `TOOLS\Migrate-HermesProfiles.ps1` now owns
the topology:

| profile | MCP servers |
|---|---|
| `default` | context7, github, headroom |
| `roblox` | + the official Roblox Studio MCP (`%LOCALAPPDATA%\Roblox\mcp.bat`) |
| `skyrim` | + houseCARL |

Forge MCPs are **not** members of any of them. Skyrim Forge and Spooky's
AutoMod stay installed and reachable through their skills and CLIs;
`-WithForgeCompatibility` is the explicit opt-in that connects Forge's MCP, and
it refuses rather than guesses when the target is missing.

The migration is backup-first and idempotent: exact config bytes are copied to a
timestamped rollback directory and hash-verified before the first write, a
failed verification restores those bytes and deletes profiles the failed run
created, unknown user MCP entries are reported as untouched rather than
normalized away, and a second run reports `no-op` and changes nothing. It writes
a `kept / migrated / removed / newly_created / untouched` ledger next to the
backup.

A game profile is created only when its local capability is actually installed,
so a machine without Roblox Studio does not get an empty `roblox` profile
pointing at a launcher that is not there.

**Verified on this machine**, all five servers completing a real handshake:
context7 (2 tools), GitHub (45), Headroom (3), Roblox Studio (27), houseCARL
(45). Re-running the migrator reports `no-op`.

### PowerShell 5.1 corrupts `hermes config set`

The first implementation drove the migration through `hermes config set` with
nested JSON arguments. Windows PowerShell 5.1 mangles those on the way to a
native executable — values containing spaces re-split, and `enabled: true`
arrived as a malformed YAML key. The verification caught it and the rollback
fired correctly, which is the only reason this is a footnote rather than a
wrecked config. The migrator now goes through Hermes' own Python config API and
passes the map in an environment variable. A contract asserts `config', 'set'`
never reappears in that script.

## Compression tuning adopted

The shipped Hermes starter now matches the tuning that was running in
production: compression triggers at **160,000** tokens rather than 120,000, and
targets **0.25** rather than 0.30. `threshold_tokens` is a *cap* on
`context_length * threshold` (`agent_init.py` passes it as
`threshold_tokens_cap`), so on the 1M-window default this buys 40k more usable
context before anything is summarized.

`proactive_prune_tokens` was set to 0 — disabled — and is restored to 80,000.
Disabling it does not save prompt cache; it defers the work to a *full*
compression, which rewrites the entire middle window (a strictly larger cache
invalidation) and summarizes reasoning rather than just oversized tool results.
Between 80k and the 160k trigger it is the only mechanism running at all, so
turning it off means flying from 80k to 160k carrying every raw blob and then
taking the whole hit at once. It is already gated to fire episodically:
≥12,000-char results only, ≥32,768 tokens reclaimed per commit, plus a regrowth
rearm.

Raising the trigger makes proactive pruning *more* valuable, not less.

## A contract that was never running

`test_hermes_native_profile_migration_contract` — written to guard the profile
migration, in the same change that added it — was defined but never added to the
explicit `tests = [...]` list that CI iterates. It passed under `pytest` and was
invisible to `python TESTS/test_release_contract.py`, which is the form CI runs.
So did `test_same_version_forge_hotfix_refreshes_shipped_content`.

Both are registered, and `test_every_defined_contract_is_actually_run` now
compares the module namespace against the list so the two cannot drift again.
It was falsified before shipping: deleting one entry makes it fail.

Its first cut had the bug it exists to catch. Anchoring on `source.index("    tests = [")`
matched the guard's **own source line**, which is earlier in the file, sliced
the wrong region, found zero registered names, and reported all 67 contracts as
orphans. It anchors on the last regex match now, with a comment saying why.

## Measured: tool count is the wrong unit, again

While deciding what belongs in the Hermes `skyrim` profile, both game servers
were measured with `TOOLS\Measure-McpSchemaCost.ps1` (real `initialize` ->
`tools/list`) rather than reasoned about:

```
houseCARL 1.9.0      45 tools  167,072 bytes  ~41,768 tokens/turn
skyrim-forge 6.0.0   52 tools   17,488 bytes   ~4,372 tokens/turn
```

**Skyrim Forge has seven MORE tools and costs a tenth of the context.** Ranking
these by tool count -- the intuitive way, and the way a `/mcp` listing invites
-- puts Forge first in line to be cut, which is backwards by an order of
magnitude. houseCARL's schemas carry deep nested record objects: three tools
(`bulk_create`, `create_record`, `bulk_apply`) are 41,596 bytes between them,
more than the whole of Forge. Forge's are typed and narrow, ~336 bytes each.

houseCARL at ~41,768 tokens is roughly 21% of a 200k window consumed before the
first user message. That is not a reason to drop it -- live MO2 load-order
truth, conflict trees and keyless Nexus lookup have no cheaper substitute, and
guessing at load order is the failure this pack exists to prevent. It is a
reason it must never be always-on, which is exactly where the `skyrim` profile
puts it.

Recorded in `BUNDLED-TOOLS/capability-records/game-mcp-schema-cost.json` and
quoted in the `capability-profiles` skill, so the next person can check the
numbers instead of trusting a changelog.

## Also

- `Test-Installed-State.ps1` and `check_versions.py` no longer demand a version
  string from a file that no longer exists.
- `Resolve-UabsProviderExe` and `Get-UabsInstalledProviders` live in

  cannot disagree about what "installed" means — which is exactly how the
  install-everything behavior survived unnoticed.

  untracked debris in the repo root.

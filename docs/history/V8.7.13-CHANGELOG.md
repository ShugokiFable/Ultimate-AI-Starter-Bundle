# v8.7.13 -- Windows PowerShell 5.1 fresh-install repair

The v8.7.12 doctor selected `--help` for Hermes and `--version` for the other providers through a one-item array. Windows PowerShell 5.1 unwraps that array to a scalar string; splatting the scalar passed the option one character at a time. All five providers therefore rejected `-`, even though their earlier installer checks and MCP handshakes had succeeded.

The provider branch now invokes literal arguments. A release contract rejects the PS5-unsafe splat, and the exact live doctor is exercised under Windows PowerShell 5.1.

Two convergence edges found after the repaired doctor were tightened as well:

- A copied skill sharing a name with Codex's own `.system` skills cannot remain useful as a customization; it only creates a duplicate index entry. The installer now backs up and moves such a shadow even if an obsolete provider rewrite changed it. Modified plugin-owned skills that do not collide with a provider built-in are still preserved.
- The all-in-one installer now checks the Hermes profile migrator's child exit code before recording the profiles as evaluated. Profile writes remain transactional and backed up by the migrator.

- 167 canonical skills across five provider trees.
- No MCP registration or schema-budget expansion.
- RTK remains default-installed at 0.47.0 behind the bundle's narrow measured allowlist; broad upstream rewriting remains disabled.
- Windows MCP remains installed and off by default.

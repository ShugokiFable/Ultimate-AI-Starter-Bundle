# v8.6.9 -- the preset was fine, the model settings were not

**2026-08-27.** Based on v8.6.8. **164 canonical skills**, unchanged. v8.6.5
shipped a correct LM Studio preset and called the problem solved. It was not:
the preset was sitting on top of four saved model configs that could not load.

---

## Two places, and only one of them wins

LM Studio keeps these separately:

| | where | what it holds |
|---|---|---|
| preset | `~/.lmstudio/config-presets/*.json` | sampling, and a `load` block only if you put one there |
| **saved model settings** | `~/.lmstudio/.internal/user-concrete-model-default-config/**.gguf.json` | the per-model load block LM Studio actually applies |

The shipped `Hermes 16GB` preset was right. It did not matter, because the model
being loaded had its own saved settings and those are what took effect.

Read off the machine, for one 27B family:

| quant | saved by hand | verdict |
|---|---|---|
| `UD-IQ3_XXS` | ctx 65,000, K/V **q8_0**, 1 session, 100% | **18.32 GiB** on a ~14.5 GiB budget |
| `UD-Q3_K_XL` | ctx 64,000, q8_0, **2 sessions**, **75% offload** | over, and a quarter on the CPU |
| `UD-Q2_K_XL` | ctx 64,000, q8_0, **3 sessions** | triple cache |
| `UD-IQ2_S` | ctx 64,000, q8_0, 100% | over |
| `Q2_K` | ctx 66,000, **q4_0**, 1 session | the only correct one |

Four of five unloadable. The one in daily use over by **3.83 GiB**, so llama.cpp
spilled to system RAM over PCIe on every session. LM Studio validates none of
this, and the three settings responsible all read as though they are free:

* **cache quantisation** -- `q8_0` is double `q4_0`, `fp16` is quadruple
* **numParallelSessions** -- a *multiplier* on the entire cache
* **offloadRatio** -- anything below 1 puts layers on the CPU

## `Optimize-LMStudioModelConfig.ps1`

```powershell
.\Optimize-LMStudioModelConfig.ps1              # print the plan, write nothing
.\Optimize-LMStudioModelConfig.ps1 -Apply       # back up, then write
.\Optimize-LMStudioModelConfig.ps1 -ReserveGB 3 -Apply
```

Reads each GGUF's geometry, computes the largest context that genuinely fits at
`q4_0`, writes it with one session and full offload. Dry-run by default, backs
up first, and floors the context at 4096 -- flooring a tiny budget to a multiple
of 4096 produced `ctx 0` on the 14.26 GB quant during development, and zero is
not a setting.

One incidental bug worth recording: the GGUF metadata helper was first written
as `Md`, which is a built-in PowerShell alias for `mkdir`. `Md 'block_count'`
did not read a key, it **created a directory called `block_count`**. Renamed to
`Get-GgufKey`.

## `Get-KvBudget.ps1` stopped guessing

The old budget was `total - 1.5 GB`. On a real desktop that is optimistic.
Measured with **no model loaded at all**:

```
16376 MiB total, 6660 MiB used, 9386 MiB free
```

6.6 GB was Claude desktop, Discord, Steam, Edge WebView2, ArmouryCrate, Razer
and Explorer. The old formula said a 10.26 GB model fit; only 9.2 GB was free,
so the **weights alone** did not.

It now prints both — the lean-desktop budget and what is free right now — and
says plainly when the second one is worse.

## Which quant, as arithmetic

Bigger quant means less room for cache, so on a fixed card the two trade
directly. 27B, RTX 4080 SUPER (16 GB), K/V `q4_0`, lean desktop:

| quant | weights | max context | reaches 65,536? |
|---|---|---|---|
| `UD-IQ2_S` | 9.36 G | 82,756 | **yes**, +17,220 |
| `UD-IQ3_XXS` | 10.26 G | 68,205 | **yes**, +2,669 |
| `UD-Q2_K_XL` | 10.94 G | 57,268 | no, 8,268 short |
| `Q2_K` | 11.80 G | 43,394 | no |
| `UD-IQ3_S` | 12.88 G | 25,972 | no |
| `UD-Q3_K_XL` | 14.26 G | **3,710** | no, 61,826 short |
| `Q3_K` | 14.43 G | 967 | no |

`Q3_K_XL` is the instructive one. Its 14.26 GB of weights **do** fit on a 16 GB
card — with 0.2 GB left, which buys 3,710 tokens of cache. Any check that asks
"do the weights fit" will bless it, because the window you asked for is not part
of that question.

## Contract

95 contracts, green. The new one asserts the optimizer writes `q4_0`, pins one
session, forces full offload, backs up before writing, stays dry-run by default,
and cannot emit a context below 4096. Falsified four ways; it catches all four.

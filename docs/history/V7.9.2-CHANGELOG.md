# V7.9.2 — the pin held, the package died

*2026-08-20*

Four defects found by an independent audit of 7.9.1, plus the token-efficiency
work they led to.

## The GitHub MCP server was a deprecated package

`TOOLS/Add-Reasoning-MCPs.ps1` wired `@modelcontextprotocol/server-github@2025.4.8`
and called it the official GitHub server. npm's own metadata says otherwise:

```
deprecated = 'Package no longer supported.'
```

It came from the MCP reference-server collection, which was archived. GitHub's
actual server is `github/github-mcp-server` — MIT, active, v1.10.1.

The instructive part is in this repository's history. `docs/history/V7.7.11-CHANGELOG.md`
records that this exact line *had no version pin*, and fixed it by pinning to
`2025.4.8`. **The pin worked. The package died anyway.** A pin freezes the
version; it does not tell you the upstream is gone. Catalog entries now carry a
`version` field to check against upstream, not only an argument to trust.

The replacement ships Windows binaries rather than an npm package, so it is
vendored as a SHA-256-pinned offline asset (`kind: mcp-binary`, `install:
zip-extract`) exactly like houseCARL, and registered by absolute path.
`Add-Reasoning-MCPs.ps1` assumed npx in four places and said so in its header;
each server now carries its own `command`, and a server whose command does not
resolve is skipped with a reason rather than written into a config as a path
that silently produces no tools.

It is registered with a **scoped** toolset list:

```
stdio --toolsets context,repos,pull_requests,actions,issues
```

The server groups its tools into 20 toolsets. `--toolsets=all` would put every
group's schemas into every provider's context on every turn, for tools nobody
calls. Widen it per project, never globally.

## Replacing it on machines that already have it

Swapping the catalog entry only helps a fresh install. The installer's dedupe
keys on the server NAME, and every existing machine has one called `github` --
so an upgrade would see it present and keep the withdrawn package forever.

Retired entries are now removed before the add-if-missing pass, in all four
config shapes, and the current definition is written in their place. A withdrawn
package is not user configuration worth preserving.

Three bugs surfaced while proving that on a real machine, each invisible to a
structural test:

- The TOML table matcher ended a table at the next `[`, but `args = ["-y", ...]`
  contains one -- so the matched text stopped *before* the package literal and
  the entry was never detected. A table ends at the next line that starts a
  header. Sub-tables are removed with their parent, or `[x.github.env]` is left
  orphaned.
- Hermes was checked against `hermes mcp list` output, which prints names and
  not the commands behind them, so the literal could never appear. It reads the
  stored config now.
- The TOML writer escaped a backslash as four rather than two, producing a
  `command` that parses back to a doubled separator and a path that does not
  exist -- the silent-no-tools failure again, in the fix for it.

All five provider configs on the development machine were migrated and verified
byte-for-byte afterwards, and the installed server was confirmed to start and
complete an MCP session over stdio.

## Playwright was unpinned

`@playwright/mcp@latest`, in the same catalog whose sibling entry explains why
unpinned npx is dangerous and whose installer comment documents a real incident
caused by it. Pinned to `0.0.79`.

## Perplexity is key-gated and did not say so

`api_key_optional: false`, yet listed in `required_for: ["web-research"]` with
nothing marking it as unavailable on a keyless machine. Now carries
`key_required: true` and leads its scope note with the requirement.

## Token efficiency

New canonical skill `token-efficiency`, fanned to all five providers (143 per
provider now).

It exists because the intuition it corrects is widespread and expensive:
*prompt caching is cheap, so an agent should watch a long job from beginning to
end.* The pricing says otherwise — a cache **read** is 0.1x input, but a cache
**write** is 1.25x-2x, and caching does nothing at all for output. An agent
polling CI forty times over a 150k-token session sends 6M input tokens and forty
replies saying "still running."

The rule the skill teaches is that the **harness waits and the model sleeps**: a
backgrounded shell condition costs zero model tokens and wakes the agent once.

```bash
until [ -z "$(gh run list --commit "$SHA" --json status \
    --jq '.[]|select(.status!="completed")')" ]; do sleep 30; done
```

It also carries the measurement that makes the case for lazy loading concrete:
this pack's 142 skill bodies total ~153,000 tokens, while the name-and-description
index an agent actually needs is ~5,500. Skills load by description and are
therefore nearly free; **MCP tool schemas are not lazy** and cost context on
every turn for every connected server. That is the reason the GitHub server above
is scoped rather than enabled wholesale.

## Known limits

- The vendored GitHub server is the **Windows x86_64** build only, matching this
  pack's installer target. A Linux or arm64 machine needs the matching release
  asset; the catalog records the version so the mismatch is visible.
- `github-mcp-server` still needs `GITHUB_PERSONAL_ACCESS_TOKEN` for anything
  beyond public reads, exactly as its predecessor did.
- The capability-profile router — loading MCP servers per project type rather
  than globally — is designed but **not** built in this release. The scoped
  toolsets are the first step toward it, not the whole thing.

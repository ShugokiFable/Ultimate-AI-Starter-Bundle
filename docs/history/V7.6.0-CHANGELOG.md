# v7.6.0 — the preamble told four agents they were a fifth product

Found by reading what actually landed in each provider's instruction file
instead of trusting that the install had worked.

## SOUL.md claimed a provider identity

`4-PREAMBLES/SOUL.md` opened with:

```text
You are Hermes Agent, an intelligent AI assistant created by Nous Research.
```

That file is not Hermes-only. The installer injects it, verbatim, into the
marked block of **every** provider's instruction file — Claude's `CLAUDE.md`,
and Codex's, Kimi's and Grok's `AGENTS.md` — as well as copying it to Hermes'
own `SOUL.md`. So four agents were being told, in their highest-priority
instruction file, that they were a different vendor's product.

It shipped in v7.5.0 and was never corrected, because the line only looks wrong
when you read it inside a *non*-Hermes file.

The opening is now provider-neutral. `TESTS\Test-V7-Pack.ps1` section 7 fails
the build if SOUL.md ever again names Hermes, Nous, Claude, Anthropic, OpenAI,
xAI, or Moonshot — the file is shared, so it cannot belong to one of them.

Nothing else in SOUL.md changed. The unrestraint content is untouched.

## The installer re-created mojibake on every run

`Install-V5PreambleBlock` read the two preamble sources like this:

```powershell
$soul = (Get-Content -LiteralPath $SoulFile -Raw).Trim()
```

On PowerShell 5.1, `Get-Content` without `-Encoding` decodes using the ANSI
codepage — Windows-1252 on this machine, not UTF-8. `AIO-INSTRUCTION.txt`
contains three em dashes (U+2014, bytes `E2 80 94`), and each came back as three
Windows-1252 characters, which were then written out as UTF-8. Measured on the
shipped file:

```text
Get-Content -Raw : 3 mojibake sequences, 0 em dashes
ReadAllText      : 0 mojibake sequences, 3 em dashes
```

v7.5.6 swept the mojibake out of the pack's *data* but left this *read path*, so
every install put it straight back. All four installed instruction files on the
test machine carried it.

Both reads now use `[IO.File]::ReadAllText`, which honours the UTF-8 encoding.
Section 7 of the pack gate asserts the call is still there, so the sweep cannot
silently regress again.

## The block now stamps the version that wrote it

The opening marker was hardcoded `v7.5.0`, six releases out of date, so a block
wired by an old pack was indistinguishable from a current one. It is now stamped
from `VERSION.txt`. The replace pattern keys on the marker prefix rather than the
version, so older stamps are still found and replaced — no orphaned blocks.

## New: TOOLS\Repair-McpPaths.ps1

Every provider stores MCP server commands as a hard absolute path, each in its
own format: Claude JSON, Kimi JSON, Codex TOML, Grok TOML, Hermes YAML. When a
tool is upgraded the folder name changes, so five configs have to be edited by
hand — and one always gets missed. The missed one fails silently: the server
simply never connects.

That is not hypothetical. Found live on this machine:

```text
Claude : <GAME-TOOLS>/Skyrim-Forge-5.1.0/...   <- gone, MCP dead
Kimi   : <GAME-TOOLS>/Skyrim-Forge-5.1.3/...   ok
Codex  : <GAME-TOOLS>/Skyrim-Forge-5.1.3/...   ok
Grok   : <GAME-TOOLS>/Skyrim-Forge-5.1.3/...   ok
```

Four providers were updated to 5.1.3 and Claude was left behind on 5.1.0.

The script finds absolute command paths that no longer resolve, and where the
dead path contains a version-stamped directory (`Name-1.2.3`), repoints it at
the highest sibling version whose target file actually exists. Anything that
does not fit that shape is reported, never guessed at.

It does not parse the five config formats — it replaces the dead path as a
literal string, which cannot reorder or reformat a user's config, and it
preserves the slash style already in use so the diff is one version number. It
backs up before writing, and reports without changing anything unless given
`-Apply`.

It is wired into `INSTALL-V7-AIO.ps1` after all provider configs are written, so
an upgrade repairs itself. Standalone use:

```powershell
.\TOOLS\Repair-McpPaths.ps1          # report only
.\TOOLS\Repair-McpPaths.ps1 -Apply   # fix
```

## The installer could push Grok into a startup wedge

`grok-cli` 1.0.4 wedges at **eight running** MCP servers (measured: 7 running =
0ms wait; 8 = ~34900ms and the process never exits). Enabled Claude plugins with
a `.mcp.json` still load even with `[compat.claude] mcps = false`, so each one
occupies a slot that never appears in `config.toml`. The safe configured count
is therefore six.

Four of the five Grok servers were wired with `-SkipIfPresent`, so they only
re-confirm what already exists. `skyrim-forge` had no such guard and no budget
check, so a fresh install added a seventh server — and the budget check ran
*after* the write, printing a warning about a file it had already changed.

Reproduced on this machine: the v7.6.0 install run took Grok from 6 to 7
configured, with claude-mem's `mcp-search` making 8 running.

The budget is now checked before the add. If Forge would exceed it, the install
refuses and says what to do:

```text
!!  Grok already has 6 MCP servers (budget 6); skyrim-forge NOT added.
!!    To take Forge on Grok, comment out a server in ~/.grok/config.toml first,
!!    or re-run with -GrokMcpBudget 7 if no plugin adds one.
```

A server already present is still re-confirmed, so this never removes anything.
The new `-GrokMcpBudget` parameter defaults to 6.

## Verification

`TESTS\Test-V7-Pack.ps1` — **PACK GATE: PASS**, 8 sections.

Two new sections, both of which fail against the v7.5.6 tree:

- **7.** Preamble sources carry no mojibake, SOUL.md names no provider, and
  `Install-V5PreambleBlock` still uses `ReadAllText`.
- **8.** The path resolver picks the highest version that really exists (a
  higher version missing the target file is correctly skipped) and returns
  `$null` rather than guessing when the path has no version-stamped folder.

Line endings were checked per file against `HEAD`: this repo sets `* -text` in
`.gitattributes` for byte fidelity, and `MANIFEST.json` hashes depend on it.
`V7-Common.ps1` and `INSTALL-V7-AIO.ps1` remain CRLF; `SOUL.md`,
`Test-V7-Pack.ps1`, `VERSION.txt`, `README.md` and `START-HERE.txt` remain LF.

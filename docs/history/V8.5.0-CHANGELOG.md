# v8.5.0 -- A cloned profile drifts forever

**2026-08-25.** Based on v8.4.0. 159 canonical skills, unchanged. No new skills
and no new MCP servers.

v8.4.0 fixed what the skills index cost. This one fixes something that had been
silently broken for as long as named Hermes profiles have existed.

---

## The bug

`hermes profile create --clone-from default` copies default **once**. The
migration managed `mcp_servers` and nothing else, so nothing ever re-converged
the copies. Measured on the maintainer's machine at v8.4.0:

```
default   fallback_providers: laguna-s / inkling / inkling-small / laguna-xs
roblox    fallback_providers: dots-3-note-preview:free, openrouter/free
skyrim    fallback_providers: dots-3-note-preview:free, openrouter/free
```

`roblox` and `skyrim` were still running the chain from the day they were
cloned. Every other setting had moved on.

**A fallback chain is only consulted when the primary is already failing.** That
is what makes this class of drift nasty: nothing is visibly wrong, no command
reports an error, and the stale value surfaces at the one moment it is supposed
to save you.

The MCP topology was correct in all three profiles the whole time, which is why
the migration cheerfully reported *"Hermes profiles already match the target
architecture"* on every run.

## What changed

The migration now converges `fallback_providers` and `model.aliases` across
every managed profile, and the planning runs **before** the no-op check --
otherwise correct MCP topology keeps masking drifted preferences.

Two fields, two different rules, because the risk is not the same:

| Field | Rule |
|---|---|
| `fallback_providers` | **Replaced** only when absent, empty, or byte-equal to a chain this pack itself used to ship. A chain you chose is reported under `KEPT` and left alone. |
| `model.aliases` | **Additive** only, via `setdefault`. Missing recommended aliases are added; an alias you already defined keeps your value. |

Both are read back and verified after writing, so a preference that was planned
but never persisted fails the run instead of passing quietly.

```
Applying Hermes profile migration:
  SetPrefs   default  add 5 missing alias(es): gemini-flash, glm, grok, sol, opus
  SetPrefs   roblox   superseded pack default (dots-studio/dots-3-note-preview:free|openrouter/free)
  SetPrefs   roblox   add 5 missing alias(es): gemini-flash, glm, grok, sol, opus
  SetPrefs   skyrim   superseded pack default (dots-studio/dots-3-note-preview:free|openrouter/free)
  SetPrefs   skyrim   add 5 missing alias(es): gemini-flash, glm, grok, sol, opus
```

## The starter shipped no fallback chain at all

Only a commented-out `fallback_model:` example. A Hermes user on their own key
therefore had **no failover** until they wrote one by hand -- and every profile
cloned from that starter inherited the gap.

It now ships a four-deep free chain:

```
poolside/laguna-s-2.1:free -> thinkingmachines/inkling:free
  -> thinkingmachines/inkling-small:free -> poolside/laguna-xs-2.1:free
```

Ordering is not arbitrary. `laguna-s` is **text-only** on OpenRouter, so a
vision task that fails over to it loses its images; `inkling` takes text, image
and audio and therefore sits *directly* behind it rather than at the bottom. A
contract asserts that position, because moving the multimodal entry down is the
kind of edit that looks harmless.

For the same reason the vision auxiliary is pinned to a multimodal model, and a
contract fails if it is ever pointed at a text-only one.

## Every model id was verified, not recalled

The ten new aliases and the whole README cost ladder were checked against the
live `openrouter.ai/api/v1/models` list -- ids, prices, context windows and
input modalities. Nothing here is written from memory.

| Tier | Model | In / Out per 1M | Context |
|---|---|---|---|
| free | `thinkingmachines/inkling:free` | $0 / $0 | 1M, multimodal |
| daily | `deepseek/deepseek-v4-flash-0731` | $0.04 / $0.08 | 1.3M |
| medium | `google/gemini-3.7-flash` | $0.38 / $1.88 | 1M |
| medium | `z-ai/glm-5.3` | $1.40 / $4.40 | 1M |
| big | `x-ai/grok-4.6` | $2.00 / $6.00 | 500K |
| max | `openai/gpt-5.6-sol` | $2.00 / $10.00 | 1.05M |
| max | `anthropic/claude-opus-5` | $5.00 / $25.00 | 1M |

The guidance the README now gives: run Flash 0731 for most work, step up to
Gemini or GLM when planning gets hard, and reach for Grok / Sol / Opus only
after watching something cheaper actually fail. At $25 per 1M output tokens, an
afternoon of agent work costs more than a month of subscription.

A contract keeps the two honest in both directions: the README cannot advertise
an alias the starter does not ship, and the starter cannot ship one the README
never explains.

### One thing deliberately NOT made free

`auxiliary.compression` stays on the paid `deepseek/deepseek-v4-flash-0731`.
Compression ingests up to the 160000-token threshold, and the free first choice
tops out at 262K context. About **$0.006 per compression** is cheaper than one
truncated summary of a session you cannot get back. The existing cost contract
caught this when the model was briefly switched to a free one.

## The starter cannot carry machine state

This file is generated by editing a live config, which is exactly how a local
LM Studio endpoint, a hook path, or an MCP command with an absolute path gets
published. A new contract refuses to ship any of it: absolute user profile
paths, `localhost:` endpoints, a personally downloaded model, an `lm-studio`
provider block, a non-empty `mcp_servers`, or any non-ASCII byte -- the file is
written into the Hermes home and re-saved by Hermes' own YAML writer.

- One real bug fixed in the new code before it shipped:
  `ConvertTo-UabsPlain` returns `,$items` so an array survives being returned
  intact, and re-wrapping the result in `@()` nested the whole chain one level
  deep. Every fallback entry then read as `Object[]` instead of a server
  hashtable, and the ledger reported "user choice" for chains it should have
  migrated. Caught by dry-running against real profiles rather than trusting
  the plan.

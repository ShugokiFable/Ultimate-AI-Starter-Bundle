# Ultimate AI Starter Bundle — v6.8.2

Date: 2026-08-15
Base: v6.8.1

The STOP ASSUMING release. Agents have a filesystem, a search tool, Firecrawl,
and a codebase index, and still answer from memory. Efficiency that ships a
wrong path is wasted tokens: you pay once for the guess and again to undo it.

This is the same lesson as v6.5 (literalism needs a control, not another
sentence that says "be thorough") applied one step earlier: refuse the
unverified path at the moment it is written.

---

## Assumption gate

`TOOLS/hooks/assumption_gate.py`, installed by the same
`TOOLS/Install-Completeness-Gate.ps1` as the completeness gate. Same three
design rules: precise, cheap, fail open.

It refuses three shapes that are unambiguous and have already burned this pack:

1. A drive letter that does not exist on this machine.
2. Another user's home directory hardcoded into a script or config.
3. Remote content piped straight into a shell (`curl | bash`, `iwr | iex`).

It is silent on prose, help blocks, docstrings, example/template files, and
commands that create drives. Validated by running the checks over this pack's
own trees: 0 findings on real files after the false positives (syntax-colon
escapes, `config.example.toml`) were closed.

`--selftest` is required. The installer refuses to wire a gate that cannot
prove itself.

## Hermes routed through the tool

v6.8.1 documented the right Hermes path and then shipped an installer that
still wrote to `~/.hermes/config.yaml` and detected Hermes by testing for a
directory a working install does not have.

The installer now:

- finds Hermes by executable (`Get-Command` / `%LOCALAPPDATA%\hermes\...`)
- hands the merge to `TOOLS/hooks/hermes_wire.py`
- that script asks `hermes config path`, parses the existing YAML, writes
  forward-slash paths, and refuses to touch a document it cannot round-trip

The assumption gate is wired with `--all-tools` on Hermes because Hermes tool
names are not something to guess at; omitting the matcher is the documented
way to match all of them.

## The pack now gates itself

`VERSION.txt` and this index `CHANGELOG.md` are the files
`completeness_gate.py` actually looks at. Before this release the pack
declared its version only in READMEs and dated changelog files, so the gate
never fired on its own repository.

## Verify-first operating contract

`AIO-INSTRUCTION.txt` rules 4/5/9: name the tool that would settle it and use
it; ask the user for a tool when none exists; assume only as a last resort and
label it. Token budget held.

## Toolbelt inventory

`TOOLS/Build-Toolbelt.ps1` writes a machine-local `TOOLBELT.md` (under
`%LOCALAPPDATA%\Skyrim-AI-V5\`, not the repo). It lists MCP servers actually
registered per provider and CLIs actually on PATH. Agents assume partly
because they do not know what they have.

## MCP pins

`TOOLS/Add-Reasoning-MCPs.ps1` now pins exact versions and can refresh an
existing entry (`-Refresh`):

- `@upstash/context7-mcp@4.0.2`
- `@modelcontextprotocol/server-sequential-thinking@2026.7.4`

Unpinned / major-only pins left a broken npx cache on this machine: missing
`zod`, and a `@modelcontextprotocol/core` ESM hole. The AIO installer now
calls this script so a fresh install gets the servers.

Grok does not own those three servers in `~/.grok/config.toml`. It inherits
them from `~/.claude.json`. Refreshing Claude's config is what Grok actually
reads.

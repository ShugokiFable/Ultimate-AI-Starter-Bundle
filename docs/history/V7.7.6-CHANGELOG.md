# v7.7.6 - Ensure-Headroom-Grok MCP cliff guard parses

`Ensure-Headroom-Grok.ps1` built its 7-server guard warning with
`$((if($pluginActive){'ACTIVE'}else{'disabled'}))`. The extra parenthesis
makes Windows PowerShell parse `(if ...)` as a command call, so the guard
threw `if : The term 'if' is not recognized as the name of a cmdlet`
instead of printing its warning. The AIO install log showed that red error
every run; the warning line itself rendered as
`mcp-search plugin .` (empty interpolation).

Fix: dropped the redundant paren, `$(if(...){...}else{...})`. The guard now
prints `mcp-search plugin disabled.` cleanly and the install run completes
without the error. No behavior change to the cliff itself - 7 configured
servers (6 with mcp-search active) still skip headroom registration and
leave headroom Hermes/Claude-only.

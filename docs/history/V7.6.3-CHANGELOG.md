# v7.6.3 — one soul, and the docs stop teaching the bug

Both fixes in this release were found by verifying v7.6.2 rather than by a
report. Neither breaks anything; both close a path back to a bug already fixed.

## There were still two soul files

`4-PREAMBLES/` shipped `SOUL.md` and `SOUL-UNIVERSAL.md`. That split made sense
through v7.5.6: `SOUL.md` was the operator's verbatim Hermes config, opening
"You are Hermes Agent", and `SOUL-UNIVERSAL.md` was the de-branded copy the
installer gave to Claude, Codex, Kimi and Grok.

v7.6.0 removed the reason for the split. Injecting one vendor's identity into
four other vendors' agents is what made Kimi refuse its own unrestraint block,
so `SOUL.md` was genericised at the source. From that commit the two files were
byte-identical apart from a single apostrophe (`U+2019` vs `U+0027`).

The duplicate was not the real problem. `4-PREAMBLES/README.md` still said:

> `SOUL-UNIVERSAL.md` | Same content, identity-neutral first line (not "You are
> Hermes Agent")

and carried a section titled "Why two souls?" explaining that the operator's
soul "says *You are Hermes Agent* — true for Hermes, false for everyone else."
Both statements had been false for three releases. Read literally they describe
`SOUL.md` as still carrying the identity line, which is an instruction to
re-add it — reintroducing the exact defect v7.6.0 shipped to fix.

`SOUL-UNIVERSAL.md` is deleted. `INSTALL-V7-AIO.ps1` wires the single `SOUL.md`
to all five providers, Hermes included. The docs describe what the code does.

## The documented manual install taught the ANSI trap

`4-PREAMBLES/README.md` offered this for users who skip the installer:

```text
$b = "4-PREAMBLES\SOUL-UNIVERSAL.md"  # plus AIO-INSTRUCTION.txt
Get-Content $b -Raw | Add-Content "$env:USERPROFILE\.claude\CLAUDE.md"
```

That is the bug v7.6.1 removed from 25 call sites, printed as an instruction.
On Windows PowerShell 5.1 `Get-Content -Raw` without `-Encoding` decodes with
the ANSI codepage, and `Add-Content` without `-Encoding` writes it back the
same way, so every em dash in the soul lands as `â€"` in the user's
`CLAUDE.md`. Gate 7b was written to stop precisely this and never saw it: it
scans `.ps1` files, and this was markdown.

Replaced with `ReadAllText` / `AppendAllText` and an explicit no-BOM
`UTF8Encoding`. The replacement was executed against a scratch target and the
output checked: strict UTF-8, no BOM, zero `U+FFFD`, zero mojibake, all three
em dashes intact, soul text byte-identical to source.

## Gate

Section 7b gained three assertions:

- ```` ```powershell ```` fences in the docs this pack authors are scanned with

  records quote the broken form deliberately, as this file does.
- `4-PREAMBLES/SOUL-UNIVERSAL.md` must not exist.

Each was confirmed to fail before being trusted: the unsafe snippet was
reinjected (`FAIL ... README.md:52`), the duplicate soul recreated, and the
installer pointed back at it. The first attempt at the fence scanner passed
against a reintroduced bug — a `\b` written through a Python heredoc became a
literal backspace byte, so the fence was never detected and the scanner
silently examined nothing. Fixed and re-verified.

# v7.9.8 — Best tool wins: capability routing

**2026-08-21.** Based on v7.9.7.

Two objectives: repair the fresh-install path, and make the agent reach for the
strongest capability it already has instead of rebuilding a weaker one.

The principle is **not** "always use a bundle tool":

> When several tools can do the job, take the cheapest reliable one whose
> strengths match the hard part. Do not rebuild a weaker version of something
> already installed just because shell, Python or Node is familiar.

---

## The audit found the reported defect and three more

The report was that the Hermes starter config contained a live `mcp_servers`
block while the Hermes README said it was empty. Confirmed on the first read —
and it was worse than reported.

`1-TAILORED-PROVIDER-TREES\Hermes\COPY-TO-PROVIDER-HOME\config.yaml` shipped:

```yaml
mcp_servers:
  context7:            '@upstash/context7-mcp@4.0.2'
  sequential-thinking: '@modelcontextprotocol/server-sequential-thinking@2026.7.4'
  github:              '@modelcontextprotocol/server-github@2025.4.8'
  playwright:          '@playwright/mcp@latest'
  firecrawl:           firecrawl-mcp@3.24.0
```

Four separate bundle decisions contradicted at once:

| entry | the decision it broke |
|---|---|
| `sequential-thinking` | 7.9.7 measured it out of the always-on core; it is an opt-in profile `-Auto` cannot reach |
| `server-github@2025.4.8` | replaced because npm marks it *"Package no longer supported"* |
| `@playwright/mcp@latest` | the catalog pins every server; unpinned lets the tool surface change mid-session |
| `firecrawl-mcp` | documented as `-WithExtras`, so `-WithExtras` meant nothing for Hermes |

And the file's own header, three lines above the block, read:

> This file must never contain a machine username, drive letter, or **live MCP
> command**.

The rule was written down and false in the same file. Only a check holds a line
like that.

### It reaches a fresh machine

`Copy-V5StarterIfMissing` copies the template **whole** when the destination has
no `config.yaml`, and `Install-Provider-Starter-Settings.ps1` runs at line 345
of the installer — long before `Add-Reasoning-MCPs.ps1` at line 1556. Tracing
the real sequence rather than assuming:

- `github` — **self-repairing.** `Add-Reasoning-MCPs` carries a retired-literal
  sweep, detects the dead package and rewrites the official server in its place.
- `sequential-thinking`, `playwright@latest`, `firecrawl` — **survive.** Nothing
  looks at them. A fresh Hermes user got all three.

So one of the four was already handled and three were live. Worth stating
precisely, because "all five are broken on fresh installs" would have been the
easy claim and it is not true.

### Fixed at the source

`mcp_servers: {}`. MCP registration belongs to the installer and
`Set-McpProfile.ps1`, which read what is actually installed and choose the scope
each server belongs in. A template knows none of that.

Then the shape itself is refused, so the four symptoms cannot come back one at a
time. `Test-V5PortableTemplate` now rejects any starter declaring live MCP
entries in YAML, TOML or JSON, or naming an `@latest` package:

```
current templates      8 / 8 pass
defect fixtures        4 / 4 refused   (yaml, toml, json, @latest)
comment mentioning mcp_servers          accepted -- no false positive
```

## The measurement contradicted the plan

The brief assumed the bundle should wire Firecrawl into more places for Hermes.
Three measurements say otherwise.

**1. Hermes already does this, keylessly.** v0.20.4 resolves `web_search` /
`web_extract` through a keyless vendor ring — `plugins/web/keyless_mcp.py`:

```python
_KEYLESS_RING = ("exa", "parallel", "tavily", "firecrawl", "keenable")
```

Round-robin per request, rate-limit failover to the next vendor. Run with no
key and no account:

```
firecrawl_search_keyless    1.4 s   real results
firecrawl_extract_keyless   0.7 s   8,318 chars
```

**2. The MCP costs more than anything this pack has removed.** Real
`initialize` → `tools/list` via `TOOLS\Measure-McpSchemaCost.ps1`:

```
firecrawl-mcp@3.24.0   25 tools   36,337 bytes   ~9,084 tokens every turn
context7                2 tools    5,124 bytes   ~1,281 tokens every turn
sequential-thinking     1 tool     4,590 bytes   ~1,148 tokens every turn
```

7.9.7 removed sequential-thinking from the always-on core for costing ~1,148
tokens a turn. This was **eight times** that, arriving by default on every fresh
Hermes install. Eight of its 25 tools are site monitoring; five are academic
paper search.

**3. Keyless, its unique half does not work.** Calling each tool with no key:

```
firecrawl_search     OK
firecrawl_scrape     OK
firecrawl_map        ERROR  Unauthorized: API key is required
firecrawl_crawl      ERROR  Unauthorized: API key is required
firecrawl_agent      ERROR  Unauthorized: API key is required
firecrawl_interact   ERROR  Unauthorized: API key is required
```

And the native path calls the same API — `client.scrape(url, formats=["markdown"])`.

So keylessly the server duplicates exactly what Hermes already has, at ~9,084
tokens a turn, and the part that would justify the cost needs an account this
pack refuses by default — the same test that withdrew Supabase in 7.9.7.

**Not registered.** The native route is the strong one, not a compromise.
`-WithExtras` installs it deliberately when you have a key and want
crawl/map/interact.

This may also be *why* the reported behaviour happened. A weak model looking at
`web_search`, `web_extract`, `browser_*`, 25 `firecrawl_*` tools, `terminal` and
`execute_code` has many overlapping ways to fetch a page. Removing a duplicate
25-tool surface is a routing fix as much as a cost fix.

## One new skill, after auditing six

`capability-profiles`, `tool-discovery`, `ai-tooling-stack`,
`research-verification`, `tool-output-awareness` and `assumption-audit` were all
read before anything was written.

The nearest owner is `capability-profiles` — but its subject is *enabling MCP
servers*, and its description triggers on "a task needs a capability the
connected servers do not cover". **A model about to write a Node crawler does
not match that description.** These skills load by description, so content in
the wrong skill is content that never loads at the moment it is needed.

`capability-routing` owns the decision itself:

```
WHAT IS THE HARD PART?
  v  WHICH AVAILABLE CAPABILITY OWNS IT?
  v  USE THE CHEAPEST TOOL THAT FULLY COVERS IT
  v  IF IT FAILS ON CAPABILITY: ESCALATE THE CLASS
```

It carries the anti-dogma half with equal weight — read one JSON file with a
file read, GET a static URL with the native extractor, replace a string in three
files with ordinary editing. Twelve tool calls for a page `curl` answers is the
same error in the opposite direction.

It also distinguishes *why* a tool failed: "unauthorized" and "rate limited"
mean the capability was right and something else was wrong. Only "wrong class"
justifies switching.

`research-verification` gained the escalation principle at its own seam — it
already owned the **authority** ladder; this is the **capability** ladder — and
was trimmed back under the 500-word body budget rather than allowed to grow.

146 canonical skills, mirrored across five provider trees.

## Cleanup the audit turned up

### `capability-profiles` still described the world 7.9.7 replaced

It read *"## The always-on three — `context7`, `sequential-thinking` and
`github` are wired globally"*. 7.9.7 demoted sequential-thinking and updated the
script, the profile catalog and the installer — but not the skill that explains
the always-on core to the agent. The 7.9.7 gate checked
`Add-Reasoning-MCPs.ps1`, which was correct, and never compared it to the prose.

### The Hermes README was stale in four ways, not one

| README said | file actually said |
|---|---|
| Empty `mcp_servers` | five live servers |
| `reasoning=high` | `reasoning_effort: max` |
| `max_turns=350` | `max_turns: null` |
| compression at 250K | `threshold_tokens: 120000` |

Rewritten from the file, and a contract now checks each claim against it.

### `final_pack_version` removed from 37 skills

Nothing read it at runtime. Its only consumer was a release contract asserting
it stayed current — the field existed to service its own test. As a version
signal it was not merely useless but wrong: 36 of 37 had drifted.

```
final_pack_version: 4.3.0   x29
final_pack_version: 5.0.0   x6
final_pack_version: 5.1.0   x1
final_pack_version: 7.9.7   x1   (the one the contract watched)
```

Removed from 222 `SKILL.md` files across canonical and the five provider trees,
with a contract forbidding its return. `metadata.version` is deliberately kept:
a component's own version is a legitimate thing to carry and makes no claim
about the pack.

## The measurement tool 7.9.7 should have shipped

7.9.7 demoted a server on a byte count and shipped no way to reproduce it.
`TOOLS\Measure-McpSchemaCost.ps1` speaks real MCP over stdio and reports
per-tool bytes, largest first.

Building it produced three bugs worth naming, since each is the kind that fails
silently:

- **A blocking `ReadLine` inside a deadline loop.** The condition is only
  re-evaluated when a line arrives, so a server that says nothing hangs forever
  instead of reporting that it said nothing. Now an async read carries the
  deadline — and the pending task is held across iterations, because starting a
  second `ReadLineAsync` while one is outstanding throws.
- **An undrained stderr pipe.** Redirected and never read, it filled and blocked
  npx before the server could answer anything.
- **A handshake that waited for a reply that never comes.** context7 4.0.2
  answers `tools/list` but emits nothing readable for `initialize`; gating the
  second request on the first deadlocked against a server running perfectly.

The re-measurement also moved context7 from 4,870 to 5,124 bytes. All published
figures now come from this one tool, so they are comparable.

# V7.2.1 CHANGELOG — Forge venv trap fix

2026-08-15

## skyrim-forge skill

- Description no longer pins 4.2; title now says 5.x (Forge is at 5.1.0).
- New section: **Venv health (Windows) — the provider-runtime trap**.
  - Trap: venvs created from a provider runtime cache python
    (`~/.cache/codex-runtimes/...`) die when that cache is deleted or the
    provider is uninstalled. MCP clients (Grok, Claude Code, Codex, Kimi)
    hang at startup waiting on a server that cannot boot.
  - Diagnosis: `pyvenv.cfg` `home =` pointing into a cache dir.
  - Repair: rebuild the venv from a stable interpreter + `pip install <root>`
    (Forge has zero external deps and a local build backend).
  - Verification: one-line MCP `initialize` probe that must return JSON.

## Reason

Observed in the field: updating Forge 5.0.2 → 5.1.0 created the 5.1.0 venv
from the 5.0.2 venv, whose base was the Codex runtime python. Deleting the
Codex runtime cache (fresh-install cleanup) killed both venvs and hung Grok
on MCP startup. The skill now prevents this for every downloader.

## Scope

Docs/skill only. No pack-structure changes, no tool changes.

# v8.7.17 — native MCP scope and honest measurements

Codex now receives project MCPs in `.codex/config.toml`. It loads those only
for trusted projects; the bundle does not grant trust or fall back to global
registration. Restart and run `codex mcp list --json` from the project.

An existing Codex entry with custom tool filters, disabled flags or approval
settings is left byte-identical during refresh. Its transport refresh is
explicitly reported as skipped. Adding a provider merges the profile ledger
instead of forgetting providers configured earlier.

Release packaging now uses the tracked-file manifest as its allowlist. The
previous filesystem walk could include ignored Codex/Grok/Serena project
settings; neither archive now includes unrecorded machine-local files. Both
variants are tested with private-state fixtures, exact manifest coverage and
rejection of an out-of-root source path.

## What was exercised

- `TESTS/Test-McpProfiles.ps1`: isolated config writers, scope, repeat installs,
  custom-policy preservation, provider ownership and removal.
- `TESTS/test_mcp_protocol.py`: real child-process stdio, strict UTF-8 without
  BOM, zero/one/paginated tools, malformed results, duplicate tools, repeated
  cursors and quoted Windows commands.
- `TESTS/test_codex_native_profiles.py --codex <absolute executable>`: native
  Codex 0.152.0 with isolated homes, trusted/untrusted projects and an unrelated
  folder; real app-server registration filters three fixture tools to one and
  executes that harmless tool. No login or model request. This native test is
  opt-in, requires the executable and never reports a skipped test as passing.
- Context7 4.0.4: real initialize/tools-list, 2 tools, 4,864 compact UTF-8 array
  bytes. Per-tool counts were 3,038 and 1,823; array framing accounts for 3 more.

The PowerShell schema meter now uses the existing stdlib transport. The old
independent transport sent tools/list before waiting for initialize, handled
one page only and serialized a single tool inconsistently. The replacement
reports advertised schema bytes plus an explicitly labeled bytes/4 estimate.

## Correction to older release notes

Previous claims that every MCP schema is loaded and billed on every turn,
that only Hermes can filter tools, and that Codex lacks project scope were
too broad or wrong. Codex has `enabled_tools` / `disabled_tools`; Claude Code
supports deferred Tool Search. Metadata, retrieved schemas, tool results,
prompt caching, active model and deployment all affect real usage.

Historical byte records and their legacy `*_tokens_per_turn` field names are
retained for compatibility and explicitly labeled schema estimates. Older
dated release notes describe the old conclusions, not current guidance.
No loaded/cached/billed savings or model-selection reliability is claimed.

`Test-McpHandshake.ps1` uses native effective Codex discovery, respecting trust.
It then tests stdio command/args in the current shell environment. Config
env/cwd overrides and provider filters are not replayed by that smoke test;
authentication and a full model turn need separate evidence. The native fixture
test covers provider registration and a call independently.

# v8.7.1 -- current pins and honest MCP proof

**2026-08-29.** Based on v8.7.0. **164 canonical skills**, unchanged. No new
always-on schemas.

## Updated without adding tool soup

- Headroom **0.37.0**, including the exact upstream Windows wheel in the
  Full-Offline payload.
- Context7 **4.0.4**, re-measured keyless at 2 tools and 4,870 schema bytes.
- CodeBurn **0.9.23**, now installed by an exact npm spec instead of a moving
  unversioned package name.

Online and offline declarations are contract-bound to the same version. Hermes'
second Context7 writer now reads the catalog instead of carrying its own pin.

## MCP diagnostics no longer require a `python` PATH alias

The shell running the proof could reach two bundle-owned Python interpreters but
had no `python` or `py` command. `Test-McpHandshake.ps1` therefore failed before
it sent one MCP frame. The resolver is now shared with the full pack gate and
executes a real interpreter from system launchers, Skyrim Forge, or Hermes.

## Empty provider homes found what existing machines hid

Codex writes bundle skills to `.agents`, not `.codex`. A fresh install therefore
reached the instruction copy with no `.codex` directory and aborted. The shared
provider loop now creates the provider home before any writer uses it.

Claude's starter also still registered the retired `thedotmack` marketplace.
Cleanup removed it at the end of every install, so the next run added it again
and created another backup. It is gone from both shipped Claude defaults; the
explicit `-WithClaudeMem` path remains the only way to install claude-mem.

## The installed Headroom version is the version users execute

Pip installed Headroom 0.37.0 successfully into a non-PATH user Scripts folder
while `headroom` still resolved to 0.36.5 under `.local/bin`. When uv is present,
the installer now uses its isolated tool environment first, includes `[mcp]`,
records uv's actual bin directory, and releases an exact-path running Headroom
process before replacement. The active executable reports 0.37.0 and all five
provider handshakes pass.

## GitHub MCP authentication guidance corrected

The official GitHub MCP binary's built-in OAuth needs no PAT on github.com. Its
first authenticated tool call opens browser authorization; a PAT remains an
optional alternative. Initialize plus tools/list still proves only the server,
config, and protocol, not that later user authorization.

# v8.7.7 -- RTK savings without the broad rewrite table

**2026-08-31.** Based on v8.7.6. **167 canonical skills**; no new MCP
schemas.

RTK 0.46.0 is now a default component, including in the Full-Offline payload.
The upstream all-command hook is still disabled: direct probing showed it
rewrites lossy `git diff`/`show`/`log`, broken compound `find`, exact
`curl`/`gh` output, and even mutating `git add`/`commit`/`push`.

The bundle instead owns a stdlib-only fail-open hook with a measured allowlist:

- exact standalone `git status`, `git status --short`, and `git status -s`;
- standalone human-facing `pytest`, `cargo test`, and `go test` runs.

A disposable Git fixture covering staged, unstaged, deleted, renamed, Unicode
and untracked paths was line-identical 5/5 through `rtk git status`; default
status fell from 551 to 145 bytes. The test filters retain the failure summary
and use RTK's tee recovery. Machine-readable JSON/JUnit/report output, pipes,
redirection, compound commands, every mutating Git command, and every other RTK
surface remain raw. A version guard also leaves a future RTK raw until its
rewrite table is re-measured against the catalog pin.

Claude, Grok and Hermes receive the executable PreToolUse hook. Hermes wiring
is pre-only and never adds a pre-verify gate. Codex and Kimi receive the same
narrow rule in their installed instruction preamble, without claiming an
unestablished command-mutation hook. The broad Hermes `rtk-rewrite` plugin stays
disabled and doctor-visible.

Fresh-install coverage now includes the official RTK Windows archive in
`BUNDLED-TOOLS/offline` with a recorded SHA-256. The hook has a runnable
allow/deny and provider-payload self-test, is part of the pack gate, and has a
release contract binding its measured version, default component status,
provider wiring, pre-only Hermes behavior, and raw unsafe surfaces.

The live convergence run then caught two installer-boundary defects. Hermes'
verification set `HERMES_ACCEPT_HOOKS` only around `hooks list`, a read-only
command that never records consent, so a newly configured hook could not fire.
The wire helper now atomically allowlists only each exact, self-tested bundle
command, records its script mtime, backs up the prior JSON, and removes that
approval on uninstall; it never enables blanket `hooks_auto_accept`.

Codex also surfaced a locally provider-adapted `skill-creator` duplicate. It
correctly refused to delete bytes that differed from the current pack source;
the user-authorized local convergence pass backs that copy up before removing
it. Separately, the shared deduper now compares installed provider bytes to the
exact provider source rather than canonical, so future fanout changes do not
create a false “user-modified” result. It remains backup-first and still refuses
any actual local edit.

# v8.7.11 -- release-asset cache integrity

## Fixed

- `OnlineLatest` no longer trusts an existing GitHub release asset because its reused filename and byte count look plausible. Cache reuse requires the exact published SHA-256; a missing digest forces a fresh download.
- Release assets download into a unique sibling temporary file, validate against the GitHub size and digest, and replace the cache only after validation. A failed refresh leaves the prior file intact.
- `Update-From-GitHub.ps1` now uses that same shared download and integrity boundary.
- Generic ZIP installs record their executable path. RTK additionally runs its installed `--version` and must match CATALOG before the component can be recorded as installed.
- The installed-state doctor independently executes the RTK binary that wins on PATH and fails when it differs from CATALOG. This exposes the concrete regression found during the v8.7.10 live audit: the active binary was 0.46.0 while CATALOG and Full-Offline correctly carried 0.47.0.

## Proof added

- `TESTS/Test-ReleaseAssetCache.ps1` runs under Windows PowerShell 5.1 and proves rejection of same-name/same-size stale bytes, wrong sizes, malformed digests, and digest-less cache reuse. It also proves a valid refresh, valid reuse, and preservation of the last known-good file after a corrupted refresh.
- `TESTS/test_release_contract.py` binds installer, updater, doctor, and full-pack invocation to the shared integrity boundary. The suite contains 124 contracts in this release.

No skills or MCP schemas changed; the pack remains at 167 canonical skills across five provider trees.

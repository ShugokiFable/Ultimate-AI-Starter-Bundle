# v8.4.0 -- The index was the bottleneck

**2026-08-25.** Based on v8.3.0. 159 canonical skills, up from 146. No new MCP
servers.

v8.1.0 decided which servers a machine pays for. v8.2.0 decided how much of each
one. v8.3.0 removed what the installer left behind. This release is about the
one budget none of those touched: the skills index itself.

---

## Codex was routing on skill names alone

Codex renders its skills index into a **fixed block of roughly 22.3 KB** and
splits it across every entry. Measured with `codex debug prompt-input` against
the maintainer's live `CODEX_HOME`:

```
entries=255   description chars: min=14  median=16  max=18
```

Sixteen characters. The index literally read:

```
- adversarial-self-review: Use when finaliz (file: r0/...)
- arma3-modding: Create and repai (file: r0/...)
- skyrim-crash-diagnostics: Use when a Skyri (file: r0/...)
```

Every description in all 255 entries was destroyed. **This pack routes by
description**, so Codex was matching on skill names and nothing else.

The mechanism matters more than the number: each entry costs **~77 characters of
name and file path before it describes anything**. At 255 entries roughly
19.6 KB of the 22.3 KB budget was file paths, leaving 4 KB for meaning.

### The doctor had been reporting this as fine

It said 219 entries at ~88 chars. Both numbers were wrong:

- It counted only `~/.codex/skills`. Codex indexes **every** root -- its own
  system skills, and one set per installed plugin. That is 37 more entries than
  the doctor could see, which is how a 255-entry index was reported as 219.
- ~88 chars was an estimate that measurement contradicts. Measured: **80 chars
  at 151 entries**, and 16 at 255.

Measured curve, sandboxed `CODEX_HOME`s, one variable changed per run:

| index entries | median description |
|---|---|
| 151 | 80 chars |
| 166 | 68 |
| 181 | 56 |
| **196 (this release)** | **40** |
| 223 | 32 |
| **255 (v8.3.0)** | **16** |

Shortening descriptions is not the lever -- the allowance follows entry COUNT.
Cutting every description to 60 chars measurably gave no entry more room.

## The mega-pack: 73 skills, in four trees, in zero repositories

The Other-Games mega-pack was extracted onto the machine by hand. It sat in
Claude, Codex, Grok and Hermes and in **no repository**: no version, no backup,
no cleanup, gone on any tree reset.

Measured before consolidation:

- **67 of 73** were single-file, ~4 KB skills
- **56% of its 188 KB was byte-identical boilerplate** -- the same two blocks
  repeated in 41 files
- that boilerplate had **already drifted into two variants**: 20 of the 41 files
  had silently lost the Evidence ladder -- including `game-mod-tool-router`, the
  entry point every other skill told you to load first

Per-game unique content was 300-700 bytes. Each of those paid a full index entry.

### Consolidated, not deleted

Deleting the pack was the obvious move and it was the wrong one. It reaches
~56 chars and costs 73 games. Consolidating reaches ~40 and keeps them -- and the
per-game text goes back to **full length** inside a reference file instead of
being cut to 16 characters. Six characters of index is the entire price of
keeping 73 games.

| new skill | absorbs |
|---|---|
| `game-modding` | the router, 16 cross-game workflow skills, and 19 one-off games |
| `minecraft-modding` | 13 Minecraft skills |
| `paradox-modding` | 6 Paradox skills |
| `unity-mod-frameworks` | 10 Unity / BepInEx / Harmony skills |
| `unreal-mod-frameworks` | 4 Unreal / UE4SS skills |
| `bethesda-creation-modding` | Fallout 4, Starfield |
| `saints-row-modding` | carried verbatim (SaintsRowForge companion) |
| `roblox-game-development` | carried verbatim (RobloxForge companion) |

**The transformation is structural, not editorial.** Every game's body is carried
VERBATIM into a reference file -- verified: 68 of 68 source bodies present
byte-for-byte, every auxiliary file (`ERROR-REGISTRY.json`, `FRAMEWORK-MATRIX.md`,
`new_version.py`, `PORTING-CHECKLIST.md`, ...) carried across. The only content
removed is the boilerplate that was identical across files, now stated **once**
in `game-modding/references/MODDING-LAWS.md` as the superset of both drifted
variants.

Reference files are tier 3: loaded on demand, never charged against the index.

### Descriptions are front-loaded

At 40 visible characters the identifying clause has to come first. Every new
skill is written that way, and this is what Codex now renders:

```
game-modding                 Modding any game other than Skyrim - C
minecraft-modding            Minecraft Java mod development - Fabric,
paradox-modding              Paradox grand strategy mods - Stellaris,
unity-mod-frameworks         Unity game mods via BepInEx, Harmony,
unreal-mod-frameworks        Unreal Engine 4/5 mods via UE4SS, Lua an
bethesda-creation-modding    Fallout 4 and Starfield mods - plugins,
```

**Result: 255 entries at 16 chars -> 196 at 40.** 2.5x the description, and
every game kept.

## Five skills that existed only in Hermes

Hermes carried 28 skills no other tree had. Eight were the maintainer's own;
these five are now shipped to all four providers:

- `github-fleet-maintenance` -- one upgrade pass across an owner account
- `mcp-server-diagnostics` -- handshake, launcher, and registration faults
- `win64-native-builds` -- native Win64 C/C++ with or without the Windows SDK
- `windows-workspace-ops` -- junctions, `!`-paths, git overlays, byte-exact edits
- `c-game-regression-testing` -- single-file C games with globbed `*_test.c`

Two were **not** added as entries, because a skill that already owned the
capability was a better home than a rival with a 40-character description:

- `repo-release-sweep` -> `release-checklist/references/docs-heavy-repo-sweep.md`
- `local-ai-tooling-ops` -> `mcp-server-diagnostics/references/provider-cli-ops.md`

`autonomous-ai-agents` is not a skill at all -- it is a Hermes **category**
directory holding Hermes' own product documentation, and is left alone.

### Identity was scrubbed before any of it was published

This repository is public. `windows-workspace-ops` carried a Windows **SID**,
account name, full name, git email and machine name; `local-ai-tooling-ops`
carried absolute profile paths. `references/windows-identity-names.md` was
dropped entirely -- it is identity data, reusable by nobody -- and the remaining
paths generalized. A sweep over the **whole** canonical tree gates the release
and reports CLEAN.

## `roblox-docs` has never worked

Its `SKILL.md` is 212 bytes that end with the literal text `...[truncated]` and
never close the frontmatter. A frontmatter block that does not close is not a
loadable skill.

It ships that way from **RobloxForge v0.1.0** and had propagated into all four
provider trees on this machine, costing a full index entry while being
unloadable. Rebuilt from its own surviving description as
`roblox-game-development/references/api-docs-lookup.md`.

---

## The cleanup could not see any of this

`RETIRED-SKILLS.json` is derived from this repository's history -- deliberately,
so it cannot drift. That is exactly why it was blind here: the mega-pack's 73
names were **never in this repository**, so nothing recorded them and the loose
copies would have kept competing with the routers that absorbed them.

Derived history stays derived. A declared `ABSORBED` set is added alongside it,
for skills this pack never shipped but now supersedes. The registry goes from 8
retired names to 81.

Explicitly excluded from removal, and contract-checked:

- `saints-row-modding` and `roblox-game-development` -- now shipped canonically,
  so listing them would delete a live skill
- `autonomous-ai-agents` -- Hermes' own category directory, not ours to remove

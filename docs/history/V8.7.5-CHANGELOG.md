# v8.7.5 -- img2threejs dependency security update

**2026-08-30.** Based on v8.7.4 (c9e125f). **167 canonical skills**, no new
tools, profiles, or always-on MCP schemas.

## Fixed

GitHub reported 36 Dependabot alerts after img2threejs entered the bundle. They
collapsed to three underlying findings repeated across canonical source and
five generated provider trees:

- Transformers 4.57.6: two high and one moderate advisory lineage. The optional
  vision environment now requires and locks current Transformers 5.16.1; the
  first fixed releases named by GitHub were 5.0.0rc3, 5.3.0, and 5.5.0.
- esbuild 0.24.2: one moderate advisory lineage. The Node verification pipeline
  now pins current esbuild 0.28.2 (fixed from 0.25.0).

Both lockfiles were regenerated from their official registries, the actual
imports/build API were exercised, and the canonical tree was fanned out through
the existing single-writer generator. Release contracts now reject either old
dependency line.

The v8.7.4 Codex convergence fix is unchanged. Windows MCP remains installed
and manually opt-in.

The final extracted-artifact entrypoint test caught a separate launcher bug:
when a `.bat` was started from Codex or PowerShell 7, `cmd.exe` preserved the
parent's Core module roots. Windows PowerShell then found an incompatible
`Microsoft.PowerShell.Utility` first and the installer lost `Get-FileHash`.
Every shipped batch-to-Windows-PowerShell boundary now clears the inherited
`PSModulePath`; Windows PowerShell reconstructs its own native defaults.

Release contracts now inspect Git-tracked files in a checkout and all files in
an extracted archive. This keeps ignored `dist/` proof copies from producing
false source-name and Linux execute-bit failures after a candidate build.

# v7.7.11 — fresh-install hardening (MCP pins + houseCARL move repair)

Two fresh-install issues found while auditing a live machine that had moved
houseCARL off its default path. Both are now fixed in the tooling itself, so
new installs and upgrades cannot reproduce them.

## Fix 1: github MCP was unpinned in Add-Reasoning-MCPs.ps1

`@modelcontextprotocol/server-github` had no version pin, while the file's
own header says "Exact versions, not @latest" and every other server in the
list is pinned. Unpinned npx cold-resolves on first spawn and can reuse a
broken cache — exactly the failure mode the other pins exist to prevent.
Pinned to `@2025.4.8`, matching `TOOLS/MCP-CONFIG-EXAMPLES.toml.txt` and
README. Every fresh install now writes all three reasoning MCP servers with
exact pins. (A live machine found with an unpinned github in Hermes + Codex
configs was the symptom; this fixes the cause.)

## Fix 2: Repair-McpPaths could not repair a moved houseCARL

`Resolve-LivePath` only repoints dead paths by finding a version-stamped
sibling directory (`Skyrim-Forge-5.1.0` -> `Skyrim-Forge-5.1.3`). When
houseCARL is moved to a tools drive (e.g. `S:\Apps\Skyrim Tools\houseCARL`),
the dead `%LOCALAPPDATA%\houseCARL\...` path has no versioned sibling
anywhere near it, so the repair reported `DEAD (no replacement found)` and
"Repaired 0 of N" while the server was alive and well at the env root.

The bundle already registers houseCARL through the `HOUSECARL_MCP` user env,
which is its own registry. The resolver now consults that env when the dead
path's leaf is `housecarl-mcp.exe` — a targeted rule that cannot guess for
any other unversioned path (the "refuses to guess" property still holds and
is still tested). New test in `TESTS/Test-V7-Pack.ps1` section 8 asserts the
env fallback repoints a dead housecarl path and that arbitrary unversioned
paths still return `$null`.

## Why fresh installs are safe

- New install: houseCARL lands in `%LOCALAPPDATA%\houseCARL` (or the
  existing `HOUSECARL_MCP` root is respected), `HOUSECARL_MCP` is set, and
  all five provider configs are written in one pass — born consistent.
- Upgrade/migration: the repair script now self-heals a moved houseCARL from
  the env registry instead of leaving the provider silently disconnected.
- All npx MCP servers are written with exact pins everywhere.

PACK GATE: PASS (section 8 includes the new env-fallback case).

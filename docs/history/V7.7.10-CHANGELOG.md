# v7.7.10 - two gates were green because they stopped testing

An audit of v7.7.2 through v7.7.9. Pack gate PASS, harness 18/18, MANIFEST
verified, CI green on every commit. Two of those greens were hollow.

## The framework truth lock had been dead for a release

`_V7-CANONICAL-SKILLS/skyrim-distr-kid-validation/scripts/verify_framework_truth.py`
is the script that pins SPID and KID parser behaviour against
`FRAMEWORK-SOURCE-LOCK.json` - the thing standing between an agent and an
invented distribution key. Its first two statements were:

```python
spid=(ROOT/'skyrim-spid-distribution'/'SKILL.md').read_text(encoding='utf-8')
kid=(ROOT/'skyrim-kid-distribution'/'SKILL.md').read_text(encoding='utf-8')
```

v7.7.8 deleted both of those skills, merging them into `spid-authoring` and
`kid-authoring`. From that commit on, every invocation ended:

```text
FileNotFoundError: [Errno 2] No such file or directory:
  '...\_V7-CANONICAL-SKILLS\skyrim-spid-distribution\SKILL.md'
```

Six copies - canonical plus all five provider trees, byte-identical.

### Why nobody noticed

**No gate ran it.** The pack gate had nine sections and none of them invoked
this script. It could only have been caught by someone running it by hand.
That is the real defect; the stale path was just what happened to break first.

### The fix

The lock now reads the owning skill as a whole - `SKILL.md` plus every file
under `references/` - instead of one pinned path, because that is exactly the
kind of reorganisation that broke it. Tokens are matched against
whitespace-normalized text, so a fact that wraps across two lines still
matches; the truth is the sentence, not its column width. And a missing owner
is now a finding:

```text
FRAMEWORK TRUTH LOCK: FAIL
FAIL: SPID owner skill spid-authoring/ not found (was it renamed?)
```

Proved by renaming `spid-authoring` out of the way and confirming exit code 1,
a FAIL banner, and no traceback - then restoring it.

Pack gate section 10 runs the lock and diffs the five provider copies against
canonical.

## The consolidation itself was sound - checked, not assumed

Nine of the ten pinned truth tokens no longer matched the new owners, which
reads like v7.7.8 dropped grammar on the floor. It did not.

`spid-authoring/references/SPID-7.3.1-AUTHORITY.md` carries every locked claim,
reworded:

| old token | where it lives now |
|---|---|
| `There is no `Weapon` distribution key` | ```Weapon` is not a distributable type key`` |
| `The parser splits TraitFilters on `/`` | `TraitFilters split on `/`` |
| `` `18!` is valid `` | `deterministic Chance may end with one `!`` |
| `` `65/` `` | `actor-level ranges need both slash endpoints` |
| `DeathItem`, `GlobalLinkedFinalDeathOutfit` | `[Final]Death<Type>`, `[Global]Linked[Final][Death]<Type>` |

The last row is an improvement, not a loss: the old skill listed two example
keys, the authority file states the rule that generates all of them. KID is
the same story - `KID-4.0.6-AUTHORITY.md` states `Weapon valid / WEAP invalid
ordinary type` where the old skill explained it in prose.

The tokens were stale. The knowledge was not. Tokens updated to the pinned
wording.

## `no duplicate skills` was asserting nothing

The harness check keyed off `$pstateAll`, a map populated only in the Codex,
Grok and Kimi branches, and only for `superpowers`. Claude never wrote to it.
`ponytail` was never written for any provider. Every unwritten pair hit
`if (-not $entry) { continue }` and fell through to:

```text
Claude    no duplicate skills              PASS
Hermes    no duplicate skills              PASS
```

Eight of ten provider/plugin pairs, passing on an empty loop, while 37 copies
sat on disk.

It was also asserting the wrong thing. v7.7.5 established that Grok's TUI
Reads `~/.grok/skills/<name>/SKILL.md`, and v7.7.7 that Hermes derives
`/slash` commands and desktop autofill by scanning the same directory. For
those two providers a copy is **required**, and a missing one is the defect -
the check was still named and written for the opposite policy, patched with a
hardcoded `if ($prov -eq 'Grok' ...) { continue }`.

Now there are two explicit policies:

| policy | providers | assertion |
|---|---|---|
| dedupe | Claude, Codex, Kimi | no plugin-owned copy may shadow a confirmed native plugin |
| keep-copies | Grok, Hermes | every plugin-owned skill must be present as a copy |

Where nothing can be confirmed, it reports SKIP with the reason instead of a
free PASS.

## Which found a live defect on the first run

```text
Hermes    plugin skill copies present  FAIL  3 missing (slash commands/TUI read
                                             this path): requesting-code-review,
                                             systematic-debugging,
                                             test-driven-development
```

v7.7.7 said "Copies were restored on the live machine from the dedupe backups".
Eleven of fourteen were. All eleven carry the same 08-19 21:19 timestamp, one
restore event; the other three were not in the backup set and no later run
looked. Those three `/slash` commands had been dead since. Restored from
`1-TAILORED-PROVIDER-TREES/Hermes/`.

`%LOCALAPPDATA%\Skyrim-AI-V5\backups` - the dedupe safety net, 842 files - no
longer exists on this machine, so the pack tree is now the only recovery path.

## Line endings

`VALIDATION.json` flipped LF -> CRLF in v7.7.9, which turns every future diff
of it into a 17-line rewrite. Reverted. It was the only flip across 163 changed
files; the rest of the run held byte fidelity.

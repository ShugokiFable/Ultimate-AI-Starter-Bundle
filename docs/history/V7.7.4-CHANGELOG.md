# v7.7.4 - starter HOME, one Grok Superpowers, no Claude skill leak

The 7.7.3 installer run aborted the starter-settings pass and left Grok
with two plugins named `superpowers`. Both own `systematic-debugging`.
The TUI reports that as a Superpowers skill error.

## `$HOME` assignment

`TOOLS/Install-Provider-Starter-Settings.ps1` did:

```powershell
$home = Get-V5ProviderHome -Provider $prov -Catalog $catalog
```

PowerShell's `HOME` automatic variable is constant. On Windows that is a
terminating error (`Cannot overwrite variable HOME because it is read-only
or constant`), so none of the portable templates were merged. The AIO
caught it as a warning and continued, which is why skills still installed
and the native-plugin pass still ran.

Fix: `$provHome`. Pack gate refuses `$home =` in that script.

## Duplicate Grok Superpowers

`grok plugin list --json` on the reference machine after 7.7.3:

```json
[
  {"name":"superpowers","repo_key":"c--users-karlo-appdata-local-skyrim-ai-v5-plugins-src-superpowers-53eefb02","source":"...\\Skyrim-AI-V5\\plugins-src\\superpowers","marketplace":null},
  {"name":"superpowers","repo_key":"superpowers-21e2a56d","source":"https://github.com/obra/superpowers.git","marketplace":"xAI Official"}
]
```

`enabled = ["superpowers"]` matches both. Skill names collide.
`systematic-debugging` is the one the TUI names.

Fix: `Repair-V5GrokDuplicatePlugins` keeps the marketplace/git copy and
drops extra local clones by editing `installed-plugins/registry.json`
(not `grok plugin uninstall <name>`: that CLI matches on plugin name
only, so it removed the marketplace copy and left the local clone).
The AIO never `grok plugin install`s the staged local path when any
Superpowers is already listed.

## Claude skill leak into Grok

`[compat.claude] hooks = false` / `mcps = false` was already written.
Skills compat stayed ON on purpose in v7.4.x, when Grok was supposed to
see the pack via `~/.claude/skills` without a second copy. AIO now copies
into `~/.grok/skills` for Grok, so that reason is gone. Leaving the scan
on:

- duplicates native Superpowers skills
- surfaces claude-mem / other Claude plugin skills in Grok
- lets `mcp-search` occupy a running MCP slot even with
  `[compat.claude] mcps = false` (plugin `.mcp.json` is a different path)

`skills = false` is now part of `Set-V5GrokCompatCells` and the Grok
starter `config.toml`. `disabled_mcp_servers = ["mcp-search"]` stays.

## Kimi copies and Hermes scanner leftover

Kimi installed native Superpowers but never ran the skill dedupe, so
`systematic-debugging` existed twice. Same dedupe as the other providers.

Hermes restore of `scan_on_install` only ran when a plugin was *newly*
installed. Re-runs left `scan_on_install: false` in the live config.
Restore now always runs after the Hermes plugin pass.

## Not changed

- Unrestraint / SOUL / AIO preamble
- Forge layout (live install is `Skyrim-Forge-x.y.z` under the Skyrim
  tools folder)
- Claude / Codex / Kimi / Hermes native plugin paths

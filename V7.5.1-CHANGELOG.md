# V7.5.1 CHANGELOG — the installer finally ran on a real machine, and it broke in three places

2026-08-16

Every changelog since v6 has carried the same footnote: "the installer has not
been run end-to-end on a clean machine". This is the release where it was run
end-to-end on the operator's own machine, and the footnote earned its keep.
Three bugs, all real, all surfaced only by actually running it. None were
caught by the pack gate - which parses scripts and checks hashes, not behaviour.

## 1. The Grok config wipe (the scary one)

`Set-V5GrokCompatCells` replaces the `[compat.claude]` section when it already
exists. Its section-body pattern used `(?ms)` with a greedy `.`, and with
singleline enabled `.` crosses newlines - so on any machine that ALREADY had
the compat section (i.e. any re-run, any upgrade), the replace swallowed the
entire tail of the file. Every `[mcp_servers.*]` block after `[compat.claude]`
was deleted. Fresh installs were safe - they take the append branch - which is
exactly why v7.4.1-v7.5.0 never saw it.

Found by backup archaeology: the compat-cells step writes
`config.toml.before-compat-*.bak` before it runs, so the before/after pair
proved the wipe, and a Python replay of the old pattern confirmed it precisely.

Fix: the section body is matched line-by-line (`(?m)` only, `[^\r\n]` per
line, stop at the next `[` line). Re-ran against the backup config: all six
MCP servers survive, `hooks = false` / `mcps = false` intact.

## 2. Headroom's pip step died on PATH python choices

The `pip-or-wheel` component picked the first `python` on PATH and ran
`python -m pip`. On this machine that is the Hermes desktop's own venv
python, which has no pip - a hard crash at `$ErrorActionPreference = 'Stop'`,
aborting the whole install at the Headroom component. And even with the right
python, pip's "requirement already satisfied" goes to stderr, which PS 5.1
turns into a terminating error under `2>&1 | Out-Host`.

Fix: probe `python` / `py -3` / `python3` for an actual `pip --version`
first, blank `PYTHONPATH` around the install (the documented Hermes-venv
trap), and suspend the strict error preference around the pip call. Verified:
the exact previous failure now installs clean and continues.

## 3. Gates and reasoning MCPs silently did nothing on multi-provider installs

`powershell -File tool.ps1 -Providers $Providers` does not pass an array -
with `-File`, every argument is a literal string, and a 5-element array
unrolls into five positional arguments. `Install-Completeness-Gate.ps1`
and `Add-Reasoning-MCPs.ps1` both threw "positional parameter cannot be
found" and the installer swallowed the exception. Single-provider installs
(Hermes-only, the one this machine had in its state file) worked, so the bug
was invisible. v7.5.0's own machine had NO gates until they were installed by
hand.

Fix: pass `-Providers ($Providers -join ',')` and teach
`Add-Reasoning-MCPs.ps1` to split comma strings (it, unlike the gate, would
treat `"A,B"` as one provider).

## What was done live, and what stays

- Grok's MCP budget kept at the proven six (housecarl, skyrim-forge,
  codebase-memory-mcp, firecrawl-mcp, context7, github) - HEADROOM was
  registered by the installer run but removed again afterwards, and
  sequential-thinking was NOT added to Grok. The v7.4.3 boundary is 8
  running; 6 leaves headroom for Claude-plugin stragglers.
- Gates installed for Claude/Codex/Grok/Hermes (Kimi has no hook system -
  documented, not a bug).
- Live skill audit: PASS across the installed trees.
- The old `before-*` backup files (`config.toml.before-*`) were left in
  place as forensic evidence; only the operator's own ones.
